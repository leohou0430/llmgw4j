# 本轮审查后的实施建议

当前阶段及收尾门槛以[三步审查清单](2026-11-11-three-stage-review.md)为准：先完成第 1 步全部细节，再进入多副本治理与接入兼容性。

后续已完成准入前移、局部成本测量及标准退避提示，见 [过载审查](../verification/perf/2026-11-11/overload/README.md)。忽略提示的过载流量仍需入口限流/调用方约束；不将局部优化宣传为消除了过载退化。

范围：先维持 2C2G、单副本数据面；双副本测试只验证治理语义，不代表 HA/SLO 或扩容收益。容量、缺陷与验证依据见 [审查记录](../verification/capacity/2026-11-11/README.md)。本文件是大项方案，不代表已经实现。

## 1. 先建立可持续的资源与流契约

本批 96 VU 过载时，WebFlux JSON 成功吞吐相对 64 VU 明显下降、p99 增大。优先测拒绝路径 CPU 成本与客户端退避，使用固定 64 并发、额外过载流量的持续场景验收，分别统计成功请求 p99 和容量拒绝率，不将拒绝 RPS 计入处理收益。

保持默认 64 并发保护，根据真实请求时长分布与业务 p95/p99 目标决定准入值，不用本地 mock RPS 直接定生产容量。长生成显式配置足够的整体期限，分别监控容量拒绝、上游故障、客户端取消和截断。

SSE 单行边界已补充：JDK 字节 subscriber 在解码前按行计数，默认 1 MiB、可配置，不限制合法长流累计大小。验证和未覆盖范围见 [单行边界审查](../verification/sse/2026-11-11/README.md)。后续需结合实际供应商帧分布确认部署阈值；本地边界回归不代表生产内存 SLO。

心跳与背压审查已复现并修复 VT 共享调度线程被心跳写阻塞、两引擎提前提交响应、WebFlux 心跳溢出三个问题，见 [心跳与背压审查](../verification/backpressure/2026-11-11/README.md)。真实 TCP 慢读下的峰值内存、容器写超时和 2C2G 吞吐仍需独立测量。

EOF 末行处理已统一覆盖异步/阻塞路径，修复异步有限需求下末行丢失，见 [EOF 末行回归](../verification/eof/2026-11-11/README.md)。主动关闭 transport 的有界性及异步超时回调隔离仍需继续验证。

上游连接关闭的 POST 失败继续保留未知提交语义；只有有明确幂等保障的请求才能安全重试。容量 fixture 固定空闲连接策略，另外保留连接关闭故障场景，避免把故障重试次数当吞吐优化。

## 2. 共享账本先补恢复协议，再谈金额硬预算

现状为估算 token 原子预留、实际 usage 结算；它无法承诺严格费用上限，强杀后的预留也没有租约与恢复记录。新增持久请求 ID、幂等预留/结算、状态与恢复扫描，分别记录未提交、已提交、结果未知、已结算。

租约到期不能简单释放可能已经付费的请求：未知提交进入待核对状态，保留额度直至拿到供应商 usage/幂等查询结果或完成有记录的人工决议。价格覆盖、最大生成量和成本上界未齐备前继续拒绝生产金额预算。验收包括双副本竞争、重复结算、结算丢包、进程强杀、Redis 重启和未知提交恢复。

## 3. 版本化控制面与资源目录

Redis key 注册表当前不提供动态创建/轮换/吊销，管理端返回 501；路由和治理配置修改仍为单副本。先定义共享版本、CAS 发布、应用确认与回滚接口，再实现 Redis KeyAdminService；禁止各副本以过期配置覆盖已发布凭据状态。

文件/批任务目录按 tenant + protocol + resource ID 隔离，持久保存创建来源、路由版本、状态、TTL 和分页游标。历史任务保留可访问的来源版本；配置删除不能将轮询重定向到其他供应商。列表只查询本租户目录，不能把供应商全量列表直接返回后再补过滤。

大文件上传/下载另做 JDK Flow 字节接口与引擎桥接，保留有界缓冲、准入前鉴权、取消和生命周期结算；核心模块继续无 Spring/Reactor。验收同时记录最大驻留内存和慢客户端恢复，不以普通小文件成功替代。

上述能力按独立变更交付；当前已实施复现的传输缺陷修复、WebFlux 准入前移、两引擎容量退避提示、SSE 单行字节边界及验证工具。持久账本、分布式配置和供应商协议转换仍属于后续工作。
