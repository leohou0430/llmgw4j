# llmgw4j v0.3.1

参考 Dubbo SPI 的命名、默认实现、惰性加载和别名机制，以项目内 JDK 实现完成基础扩展发现；不直接依赖 Dubbo。HTTP 入口仍使用 Spring Boot 4 / JDK 25。

- ExtensionPoint / Extensions + META-INF/llmgw/extensions；重复名、未知名、类型与构造失败明确报错。目录实例缓存隔离，无全局实例表或隐式依赖注入。
- core/provider/tokenizer/governance 不依赖 Spring/Reactor，保留显式 Java 组装、实例状态与逆序资源关闭。
- provider/tokenizer 统一聚合 parent + API + 实现；保留原生 Flow/Future transport、Jedis 和 tokenizer 配置选择。
- 移除 dubbo-common 及其间接依赖和专用 AOT 元数据，增加禁止 Dubbo 依赖回流的规则与六项加载器回归。

v0.3.0 是直接依赖 Dubbo 的中间 tag，因目标修订取消发布，没有发行资产。本版本不移动或覆盖它。内部 Java 扩展 API/模块结构有兼容变化；HTTP 契约保持兼容，详见 [迁移说明](https://github.com/leohou0430/llmgw4j/blob/v0.3.1/docs/EXTENSIONS.md)。

发布资产：默认/Redis JAR、Linux amd64 WebFlux native、文档包、SHA256SUMS。所有构建及 native 契约成功后由流水线统一发布；不发布 Maven Central 或容器镜像。

没有性能复测，不将旧性能审查或中间构建视为当前吞吐/延迟证明。URI cache、整包文件缓冲、财务硬预算、分布式控制面和 OIDC/RBAC 等边界仍见 [配置与部署文档](https://github.com/leohou0430/llmgw4j/blob/v0.3.1/docs/DEPLOYMENT.md)。当前验证见 [审查报告](https://github.com/leohou0430/llmgw4j/blob/v0.3.1/docs/verification/architecture/native-extension-mechanism/README.md)。

English: a project-owned native named-extension mechanism inspired by Dubbo SPI, without a Dubbo dependency. Uniform modules, explicit lifecycle, Flow/Future transport and Jedis governance remain. Internal Java extensions require migration; no new performance claim is made.
