# llmgw4j v0.3.0

本版本将基础能力迁移为真实 Dubbo SPI 与显式 Java 组装。HTTP 网关仍使用 Spring Boot 4 / JDK 25，默认 JAR 支持 WebFlux、虚拟线程两引擎。

## 变化与升级

- core、provider、tokenizer、governance 基础模块移除 Spring/Boot/Reactor，Maven Enforcer 与源码检查阻止框架依赖回流。仅引入 Dubbo common，不引入 RPC、注册中心或 Dubbo starter。
- provider、tokenizer 统一为聚合 parent + API + 实现；OpenAI 轻量认证与 SDK 校验拆包。协议、认证、验证、tokenizer 和治理模块通过真实命名 SPI 发现。
- 原生 ExtensionContext 显式绑定、替换和密封，按实例管理治理状态、HTTP/Redis 客户端及关闭顺序。app 负责配置绑定和 HTTP 桥接。
- 上游异步 API 改为 JDK Flow / CompletableFuture；取消传播、背压、超时、SSE 完整性与正常结束保持连接复用均有回归。
- Redis 使用 Jedis，保留 Lua 原子记账；推荐 `gateway.redis.*`。旧 Spring 字段在 app 边缘有限兼容，旧 URL 必须拆为独立字段。
- tokenizer 显式选择生效于文本准入估算；jtokkit 需链接可选 profile。上游 usage 优先，缺失 usage 的输出仍使用启发式估算。

Java 扩展接口存在破坏性变化：UpstreamProvider/Authenticator 与 TokenCounter 迁移包名，异步返回类型、构造与模块发现方式改变。详见 [迁移说明](https://github.com/leohou0430/llmgw4j/blob/v0.3.0/docs/EXTENSIONS.md)。HTTP 路由与鉴权契约保持兼容；未知显式扩展名会启动失败或在 IO 前拒绝，不能静默降级。

## 发布资产

- `llmgw-app-0.3.0.jar`：默认内存治理，WebFlux/VT。
- `llmgw-app-0.3.0-redis.jar`：可选 Redis 治理，仍需运行时启用。
- `llmgw-webflux-0.3.0-linux-amd64`：Linux amd64 WebFlux native，下载后 `chmod +x`；其他引擎/平台按源码构建。
- `llmgw-docs-0.3.0.tar.gz`：文档、OpenAPI 与测量资料。
- `SHA256SUMS`：下载后使用 `sha256sum -c SHA256SUMS` 校验（macOS 使用 `shasum -a 256 -c SHA256SUMS`）。

Release workflow 在 JVM、Redis 和 Linux native 契约验证成功后发布资产。本版本不发布容器镜像或 Maven Central。

## 验证范围与限制

[架构重构验证](https://github.com/leohou0430/llmgw4j/blob/v0.3.0/docs/verification/architecture/native-spi/README.md)记录本地构建、真实 Redis 和双引擎契约证据。远端 Actions 对 tag 对应源码重新构建；最终资产摘要以 Release 的 SHA256SUMS 为准。

本版本没有重新测量网关性能；旧性能审查数字只代表冻结的旧产物，见 [性能说明](https://github.com/leohou0430/llmgw4j/blob/v0.3.0/docs/PERFORMANCE.md)。不承诺本次 Flow/Dubbo 变更带来吞吐或延迟收益。URI 缓存仍无上限、上传下载仍整包缓冲、原生协议注册覆盖为进程级；Redis 仅支持单节点连接池。财务级硬预算、OIDC/JWKS/RBAC、多副本配置发布与持久审计仍需外部能力。

English: v0.3.0 introduces native Java foundation modules, real named Dubbo SPI, explicit per-runtime lifecycle, JDK Flow/Future transport, Jedis governance and uniform provider/tokenizer module layouts. Internal Java extension APIs require migration. HTTP contracts remain compatible. Previous benchmark data does not establish the performance of this refactor.
