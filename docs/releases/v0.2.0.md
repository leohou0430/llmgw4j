# llmgw4j v0.2.0

本版本汇总 v0.1.0 以来的治理能力、安全审查修复与网关性能优化。JDK 25；默认 JAR 支持 WebFlux/VT，Redis 是独立可选包。

## 主要变化

- 协议与治理：多协议端点、Anthropic 认证适配、条件重试与回退、三段超时、心跳、路由及治理热更新、模型限流、缓存和请求/审计观测。
- 隔离与安全：租户/协议/参数缓存隔离、文件和任务归属及引用验证；管理写入与审计只读权限隔离；HS256 JWT issuer/audience、时间声明及 compact 格式校验。
- 一致性与容量：修复 Redis 模型桶参数与退款，治理结算退还 key/model 预留；WebFlux 阻塞治理移出事件循环，默认并发 64、非流式响应上限 4 MiB。
- 性能：SSE payload 仅复制一次，WebFlux header 第一值复制避免多值集合。局部分配下降约 22%–48% / 32%。64 个冻结产物 A/B 样本、约 422 万请求零错误；WebFlux SSE 中位数正向但范围重叠，JSON 结果波动，不承诺全面稳定提速。默认线程数仍为 32。
- 工程：117 项 JUnit、真实 Redis 测试、双引擎契约/隔离/鉴权回归；版本与脚本产物名统一，发布在所有构建及 native 流契约通过后统一生成资产与校验和。

## 升级须知

- 共享部署显式开启 `gateway.production=true`，替换 demo key、关闭 mock，并设置完整管理 token。审计只读 token 不能与完整 token 相同。
- 缺少或非本租户的资源归属返回 404；files/batches 列表、Redis 运行时 key 管理尚返回 501。
- 生产禁止使用内建金额预算；它仍是本地估算账本，Redis 不提供财务级硬预算。token 配额仍有估算误差。
- 强制审核不可用返回 503；可能已提交的付费操作不因普通超时/5xx 自动重发。
- 默认并发/响应体上限可能改变大文件和高并发行为。上传下载仍整包缓冲，URI 缓存尚无容量上限；先做容量和长期堆验证。
- JWT 是 HS256 验证器，没有内建 OIDC/JWKS/RBAC；多副本配置发布与持久审计仍需外部实现。

## 发布资产与使用

- `llmgw-app-0.2.0.jar`：默认内存治理，WebFlux/VT 两引擎。
- `llmgw-app-0.2.0-redis.jar`：可选 Redis 依赖；运行时还需启用 Redis 配置。
- `llmgw-webflux-0.2.0-linux-amd64`：Linux amd64 WebFlux native；下载后 `chmod +x`。VT native 和其他平台自行构建。
- `llmgw-docs-0.2.0.tar.gz`：说明、配置、OpenAPI 与可复现测量资料。
- `SHA256SUMS`：下载后运行 `sha256sum -c SHA256SUMS`（macOS 可用 `shasum -a 256 -c SHA256SUMS`）。

本次不向 Maven Central 发布，不发布容器镜像。性能 A/B 对应证据中冻结的审查 JAR；发布构建改变版本元数据，不能冒充已对发布资产重新压测。

详见 [性能说明](https://github.com/leohou0430/llmgw4j/blob/v0.2.0/docs/PERFORMANCE.md)、[部署](https://github.com/leohou0430/llmgw4j/blob/v0.2.0/docs/DEPLOYMENT.md)、[配置](https://github.com/leohou0430/llmgw4j/blob/v0.2.0/docs/CONFIGURATION.md)、[安全策略](https://github.com/leohou0430/llmgw4j/blob/v0.2.0/SECURITY.md)及 [完整性能报告](https://github.com/leohou0430/llmgw4j/blob/v0.2.0/docs/verification/perf/2026-11-10/perf-review/README.md)。

English: this release adds governance capabilities, fixes tenant/resource isolation, administrative/JWT authentication and Redis accounting, and reduces SSE/header allocations. The benchmark does not establish a general stable throughput gain. Production monetary hard budgets, OIDC/RBAC, distributed control-plane updates and streaming file I/O remain outside the built-in implementation. Assets include default/Redis JARs, Linux amd64 WebFlux native, documentation and SHA256 checksums.
