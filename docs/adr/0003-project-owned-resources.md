# 文件和任务归项目，而非单把key

既有实现主要按key身份隔离资源；用户在2026-11-12选择同项目多key可按权限共享文件/任务、项目之间隔离。新目录以项目作为资源归属单元，key承担授权与计量，不采用同项目不同key仍各自永久拥有一套资源的方案。

归属进入持久目录和授权合同后迁移成本较高，因此必须保留该选择的理由。此决定不允许自动合并旧资源可见范围；租户层级、成员角色、旧数据迁移和具体目录存储尚未确认，不表示已完成实现。

后续Q16确认层级为租户下多项目、项目下多key；个人场景对应一个租户一个项目。跨租户隔离要求不因项目共享而放宽；具体角色、存储和旧数据迁移尚待确定。

后续Q18确认网关只持久保存文件元数据与上游来源引用，不长期保存文件原文；上游不提供原文下载时明确拒绝。为兼容处理所需的临时数据必须有界并清理，不能把目录建设隐式扩成原文对象存储。
