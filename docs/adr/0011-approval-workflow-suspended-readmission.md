# 审批工作流以挂起-重新准入约束转发

用户于2026-11-20依据《AI Agent Handbook》第9章9.5.4选择实现审批工作流（新能力域llmgw-approval），填补治理合同中「审批未决的请求不得转为实际执行」的缺失。审批记录为持久SQLite状态机：待决 → 批准/拒绝/过期，批准可被撤销；全部迁移以WHERE state守卫的持久CAS完成，并发或重复回调只成功一次，不产生重复副作用。

审批未决不得执行：HTTP请求不长挂，提交即返回审批标识与查询路径，等待与通知由业务侧承接。审批记录绑定主体、目标、工具版本、参数摘要（调用方计算的SHA-256）与有效期；批准不意味着必定放行——执行前必须重新校验主体一致、参数摘要一致、未过期、未撤销，等待期间身份过期、参数变更或预算占用都会使重校验失败。

审批超时不自动降级为只读：超时把该次审批转为过期并终止，不把目标操作改写为只读模式，也不自动重开审批；如需只读替代方案，应形成新的可见请求并重新授权。拒绝不隐式替换工具或参数。结果未知交由业务查询或对账，网关不盲目重试。

首版触发点为MCP高风险工具策略（require-approval）；数据面模型调用不强制接入。决策与撤销经控制面API按审批自身的租户/项目范围做RBAC，原因必填并写入管理审计。审批工作流提供权限与留痕，不改变能力降级须显式授权的协议边界。
