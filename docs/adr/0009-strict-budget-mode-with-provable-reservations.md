# 严格预算模式以可证明预留收口金额承诺

用户于2026-11-20依据《AI Agent Handbook》第9章9.2.6选择在既有软预算之外提供严格预算档位。ADR-0007的估算预留与「计费可用金额不代表最终欠款严格上界」的声明在软预算档位继续成立；当租户开启严格预算模式后，金额准入预留改为可证明的最大可计费消耗：输入估算加请求显式输出上界（max_tokens / max_output_tokens / max_completion_tokens）。

严格预算模式下，缺少显式输出上界的token调用被400拒绝，不静默回软——静默回退会把软预算伪装成严格承诺，正是本章禁止的「有界超额却继续宣称严格上限」。非token单位（张数、任务数、请求体字节）的数量由请求自身界定，估算即可证明上界；证据质量为UNKNOWN的调用不可预留，同样拒绝。

重试尝试计入计划长度内的总预留占用：预留随调用终态释放或结算，结果未知保留预留待对账（与ADR-0007一致）。仅最终服务尝试向客户收费的规则不变，因此严格承诺的客户侧上界是单次尝试的最大可计费消耗；失败尝试的上游成本仍由平台承担并逐次记录，待上游成本账本落地后另行归集，不影响客户侧严格不变量。

严格模式是显式开关且默认关闭；打开它意味着接受「未带上界的调用被拒绝」这一行为变化。文档与接口声明必须如实区分两档承诺，不得以「额度」一词混同软预算与严格预算。
