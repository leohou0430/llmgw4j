## 当前兼容边界

- SQLite 为密钥、累计 token 账本、已发布路由的唯一权威；Redis profile 的治理组件不替换这三项权威。
- 旧 `/admin/routes/reload` 对权威路由源返回409；通过 `/control/routes/publish` 发布。旧 JSON 用量快照可导出观测，不能覆盖数据库；`/admin/snapshot/load` 返回409，自动恢复必须关闭。
- 新项目额度默认0。未知上游结果保持预留，同时记录失败统计；管理员核实真实用量并填写原因后才可核对，当前在途请求不可核销。
- 供应商密钥及带凭据的目录来源快照需要 `LLMGW_ROOT_KEY`，根密钥需独立备份。恢复来源所引用的外部配置和根密钥必须保持有效。
- 本轮未调用真实付费供应商；HTTP合同使用隔离的本地上游。容量数据只代表记录的四路64MiB上传、取消和管理并发场景，不外推为全部模型吞吐承诺。

默认/可选profile的26项跳过均为Redis测试，已由独立Redis完整运行覆盖。Redis完整运行之后补充的来源快照加密单测已在默认及可选profile运行。native实际平台为Darwin x86_64，未作native性能或远端OTLP收集器验证。

最后JAR的容器内存观测峰值为WebFlux **803.9MiB**、VT **667.4MiB**。数据源为`docker stats MemUsage`容器内存观测，不等同于进程RSS；cgroup配置为2CPU、2GiB且不额外放宽swap。场景和产物摘要保存在[evidence](evidence/artifacts.json)。

本次最终JAR流式脚本与native编译并行，运行到最后VT加权路由时触及执行器900秒总时限。此前全部断言无失败；保留当时仍运行的本任务实例，补完200次并发加权调用（52/148，符合1:3±12个百分点）及两个控制器单次解析检查后关闭实例。因此不把该套件写成一次完整退出0；详见[执行结果](evidence/contracts.json)、[已完成断言](evidence/stream-completed-assertions.txt)与[补验](evidence/stream-followup.json)。
