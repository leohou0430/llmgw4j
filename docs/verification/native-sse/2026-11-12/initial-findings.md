# WebFlux native SSE 性能复查（2026-11-12）

当前结论：**性能归因待低干扰环境复测，没有证明 native 或 Serial GC 是原因，也没有修改生产 Java、GC 或默认运行时。**

上一轮64并发SSE的三轮p99中位数为JVM 325.1ms、native 513.7ms（1.58倍）。`check-regression.py`按诊断阈值1.25倍可对此返回1；它不是生产SLO。

本轮只保留WebFlux SSE、64并发、12秒正式轮次与15秒预热做复测。观测到宿主正在编译LLVM：16个逻辑核心，起始1分钟负载120.4，随后仍45以上；JVM正式p99分别3018.0/898.5ms，native678.4/496.6ms，方向与上一轮不同。**环境不满足性能归因条件**。在第三轮完成前停止自己的任务，保留7个完整样本与中断日志，所有本次容器/网络已清理，未操作其他编译或应用。

上一轮原始SSE样本也显示宿主负载由28上升至45以上，尽管每容器限2CPU，也不隔离宿主调度、磁盘或内存带宽。因此旧吞吐/p99表保留为观察值，不能作为稳定回退或优化收益的证据；零异常失败、取消传播与TLS等功能结论保持各自范围。

## 实际排除与未证明事项

- Actuator system.cpu.count两种运行时均为2，已排除“native把宿主16核当成可用CPU”的直接假设。
- 构建日志证明native使用Serial GC，JVM指标显示G1；这仅证明配置不同，没有证明GC导致SSE差异。
- native的jvm.gc.pause与allocated指标返回404；不把缺失指标解读为没有GC。低干扰复测之后，若差异仍稳定，再用GC日志/支持的采样器区分暂停、分配与调度热点。
- 本轮只读Actuator观测发生在诊断试验中，不能把它当作无探针正式基准。

## 本轮改进与验证

`bench/capacity/run.py`新增`--max-host-load-ratio`，默认1.5：创建资源前、每个trial前后检查宿主1分钟负载/逻辑核心数。运行中超限仍保留样本，标记`performance_valid=false`并清理自己的资源。显式0仅供诊断，生成样本也不标记为有效性能样本。这是粗筛，不保证没有干扰；后续仍需空闲宿主与交错多轮复测。

`check-host-load.py`验证阈值、显式诊断跳过及超限时在Docker/产物读取之前退出；实际当前环境也被拦截，退出2，见guarded.log。Python编译、模块布局、原生边界、6项原生规则和git diff --check通过。

## 证据

- `bench/results/native-sse-2026-11-12/repro/`：固定产物与脚本摘要、7个已完成样本、原始日志；本次中断批次不可判为通过。
