# T2.3/T2.4 加固：网关命名空间 x-llmgw-* 出站无条件剥离

日期：2026-11-14　模块：llmgw-governance-default（基础，无 Spring）　接缝：`AllowListHeaderPolicy.toUpstream`

## 背景（计划项）

子计划 `docs/plans/2026-11-13-stage2-files-bounded-streaming.md:71` 记录阶段 1 范围外项：
binary/upload 路由 pass 头未**无条件**剥离 `x-llmgw-*`（VT:219,516；Webflux:320,1002），
要求在 T2.3/T2.4/T2.7 一并加固并回归。

## 根因

`AllowListHeaderPolicy.toUpstream` 的 `ALWAYS_DENY` 只含 authorization/transport 头，
不含网关自有 `x-llmgw-*` 命名空间（遥测 `X-LLMGW-Overhead-Ms`/`X-LLMGW-Upstream-Ms`、
控制提示 `x-llmgw-no-cache`/`x-llmgw-allow-degradation`）。默认 allowlist 不匹配该前缀时偶然被剥离，
但一旦部署配置宽 allowlist（`*` 或 `x-*`），调用方即可把伪造的 `x-llmgw-*` 头转发上游——命名空间 spoofing。
两引擎所有路由（JSON + binary/upload）的 pass 头均经 `headerPolicy.toUpstream`（VT:223/380/520；Webflux:1040 等），
故在策略层无条件剥离即覆盖全部路由。

## 实现

`toUpstream` 的拒绝条件追加 `|| name.startsWith("x-llmgw-")`（name 已小写），与 `ALWAYS_DENY` 同级，
对 upload 与非 upload 一律生效，先于 allowlist 匹配。类 javadoc 记录该不变量。

安全性核对：网关自身从 **clientHeaders 直接** 读取这些提示，不经 pass map——
`x-llmgw-no-cache`（VT:407 / Webflux:403）、降级授权 `degradationGrantValue(clientHeaders)`（VT:389 / Webflux:389,1176）。
故剥离出站 pass 不影响网关消费；既有 `withoutDegradation` 显式剥离作为纵深防御保留不动（最小改动）。
