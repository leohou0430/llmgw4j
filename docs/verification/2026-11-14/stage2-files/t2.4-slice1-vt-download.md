# 第二阶段 T2.4 切片1：VT Files 二进制内容下载流式化

日期：2026-11-14。落点：`llmgw-engine-vt`（VirtualThreadGatewayController）。本文件记录本轮实际测量，不改写历史测量。

## 范围（本切片）

仅把 **二进制内容下载**（`/v1/files/{id}/content` → `application/octet-stream`，以及 `/v1/videos/{id}/content` → `video/mp4`）从整包 `fetchRaw(byte[])` 迁移到 `fetchStream(Flow.Publisher<ByteBuffer>)` 的有界阻塞 drain。JSON 轮询/列表/删除/models/batches（`application/json`）**保持 fetchRaw 不变**，判别式 `stream = !APPLICATION_JSON.equals(contentType)`。Files **上传**流式化与 WebFlux 桥（T2.3）仍在后续切片。

## 交付

- `handleStickyFetchWithinCapacity` 增加 stream 分支：
  - 先设 status 200 + contentType + `OVERHEAD_MS=preflight`（首字节即提交响应，故头必须先于 drain；上游计时走 meter，与既有流式约定一致）。
  - `provider.fetchStream(methodFetch(...)).subscribe(new ServletDrain(out))` → `drain.await()`。
  - drain 错误 → `asException` 抛出，复用既有 catch：未提交→真实 502；已提交→不改状态（截断）。`breaker.recordSuccess/recordFailure`、`GatewayPipeline.finish` 语义不变。
- `ServletDrain implements Flow.Subscriber<ByteBuffer>`：**一次一块**背压（onSubscribe request(1)，每次写成功再 request(1)），ByteBuffer 拷成 byte[] 写 servlet 输出后即丢弃，**绝不整包**。写失败（客户端断开）→ `sub.cancel()` 释放上游源 + 记 terminal error。ByteStream 在请求线程同步发射，故 JDK 传输下 `await()` 立即返回；`await` 把 InterruptedException 转 IOException 并复位中断标志。
- `asException(Throwable)`：Exception 原样抛，Error 包 IOException。

## seam 集成测试（`FilesStreamingDownloadTest`，Proxy servlet 桩 + 真实控制器，3 测试）

- streamsFileContentInBoundedChunks：100000 字节 payload → status 200 + octet-stream + 逐字节一致 + **streamCalls==1 / rawCalls==0** + **chunkWrites≥2**（证明分块非整包）。
- upstreamErrorBeforeFirstByteIs502：源首块即抛 IOException → status **502** + streamCalls==1 + 响应为 error 信封（非空 200）。
- clientDisconnectCancelsUpstreamAndClosesSourceOnce：servlet 输出首块后抛 IOException（客户端断开）→ **上游源 close 恰好一次**（资源释放）。
