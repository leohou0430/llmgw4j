# 第二阶段 T2.5：multipart 流式扫描器（core 纯 JDK）

日期：2026-11-14。落点：`llmgw-core` 新 `core/multipart` 包。纯 JDK，无 Spring/Reactor/HTTP。本文件记录本轮实际测量。

## 交付

- `MultipartScanner.scan(ByteStream.Source, String boundary, Limits)`：流式 multipart/form-data 扫描器，逐块读取 pull 源，**不整包持有正文**。
  - 跨 chunk 边界：每次仅保留 `delimiter.length-1` 字节重叠窗口 + 一个 chunk，分隔符被分片仍能命中（测试用 7 字节 chunk 强制所有边界/头分隔符分裂）。
  - 文件内容**计数即丢弃**（Count sink），非文件字段值在有界预算内收集（Collect sink）。
  - 提取路由相关表单字段（name→value，如 model/purpose），统计文件部分数与文件字节、整体字节。
  - `trailingFieldAfterFile`：任一非文件字段出现在文件部分之后 → true（T2.6 有界 spool 触发信号）；全部字段在文件前 → false（直通快路径）。
  - 限额：单文件 ≤ maxFileBytes、单 multipart ≤ maxMultipartBytes（按累计 pull 字节）、非文件元数据累计 ≤ maxMetadataBytes；越限抛 `MultipartLimitException(Limit.FILE/MULTIPART/METADATA)`。畸形/截断抛 IOException。
  - `Limits.defaults()` = 64MiB / 66MiB / 64KiB（与子计划 §1 一致）。
  - 所有权：scan **不关闭源**（调用方持有生命周期；spool tee 须保持打开以供转发）；越限时由调用方关闭。
- `MultipartLimitException extends IOException`：携带 `Limit` 枚举，供引擎映射 413 原因（T2.7）。
