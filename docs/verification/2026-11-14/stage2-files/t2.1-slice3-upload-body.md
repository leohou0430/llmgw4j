# 第二阶段 T2.1 切片3 / T2.2 上传：流式上传体取代 rawBody

日期：2026-11-14。落点：`llmgw-core`（合同）+ `llmgw-engine-api`（路由组装）+ `llmgw-provider-http-jdk`（唯一 JDK 传输）+ 两引擎调用点。纯 JDK 基础模块，无 Spring/Reactor（HTTP 仅出现在引擎/传输）。本文件记录本轮实际测量。

## 交付（协调一次性落地，不留 byte[] compat shim）

- `ByteStream.ofByteArray(byte[])`：新增冷流工厂 + 私有 `ByteArraySource`，按 16KiB 块 `ByteBuffer.wrap` 切片（零拷贝），EOF 返回 null，close() 无资源。作为仍持有整包 byte[] 调用点的过渡桥；真正流式读取（spool）随 T2.5/T2.6 替换。
- `UpstreamRequest`：记录分量 `byte[] rawBody` → `ByteStream body, long bodyLength`（arity 11→12）。
  - 10 参便捷构造器委托 `null, 0`；6/8/9 参不变。
  - 紧凑构造器 `binaryBody = body != null`：二进制体保留 multipart Content-Type（boundary 在其中），仍剥离 authorization/host/content-length/x-api-key；非二进制体另剥 content-type/accept。
  - `forRoute`：`body == null` 才做顶层 model 重写；原样透传 `body, bodyLength`（同一冷流引用穿过路由）。
- `EngineRoutes.postRawBytes(ByteStream body, long bodyLength, ...)`：签名由 `byte[]` 改为流式体 + 精确长度；不再 `body==null?new byte[0]`（调用点恒传非空体）。
- `JdkHttpUpstream.build`：`request.body() != null` → `HttpRequest.BodyPublishers.fromPublisher(request.body(), request.bodyLength())`，**不再 `ofByteArray` 整包发布**。
- 两引擎上传调用点（VT `VirtualThreadGatewayController:523`、WebFlux `WebfluxGatewayController:1010`）：以 `ByteStream.ofByteArray(body), body.length` 包装既有 byte[]（过渡，待 T2.3/T2.4/T2.5 真正流式读取入站体）。各加 `ByteStream` import。

## seam 测试

- 传输 seam `UploadStreamTest`（1 测试，com.sun.net.httpserver 回环，无引擎）：256KiB `Random(42)` 负载经 `ByteStream.ofByteArray` + 12 参 `UpstreamRequest` → `fetchRaw`；断言上游 `readAllBytes()` 与负载**逐字节一致** + 响应体一致。证明体经 `fromPublisher` 流式投递而非整包发布器。
- 合同 seam `UpstreamRequestTest.streamingBinaryBodyKeepsContentTypeAndSkipsModelRewrite`（新增 1 测试）：二进制体保留 Content-Type、剥离 Authorization/Content-Length/X-Api-Key；`forRoute` 后 `assertSame(body)`、`bodyLength==3`、`rawJson==""`（跳过 model 重写）、apiKey 换为路由凭据。
