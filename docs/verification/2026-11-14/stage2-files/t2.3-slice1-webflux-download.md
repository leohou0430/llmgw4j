# T2.3 切片1：WebFlux Files 二进制内容下载流式桥

日期：2026-11-14　引擎：llmgw-engine-webflux　接缝：真实控制器 `handleScopedFetch`（经 reactive HttpHandler）

## 目标

Files 二进制内容下载（`GET /v1/files/{id}/content`，`application/octet-stream`）必须把
`UpstreamProvider.fetchStream` 的冷 `Flow.Publisher<ByteBuffer>` 适配为有界 `Flux<DataBuffer>`，
在事件循环之外写出（绝不整体缓冲为一个 byte[]），完成时释放上游 source 恰好一次；
首字节前的上游失败必须渲染为真实 502。JSON 元数据 GET（`GET /v1/files/{id}`）保持 `fetchRaw` 路径。

## 实现

`WebfluxGatewayController.handleScopedFetch`（llmgw-engine-webflux）在准入/归属/settled 之后按
`boolean stream = !EngineHeaders.APPLICATION_JSON.equals(contentType)` 分流：

- 流式分支：`breaker.allow` 守卫 → `markUpstreamStart` → 先置 `200`/contentType/`OVERHEAD_MS=preflight`
  （首字节提交前可改）→ `JdkFlowAdapter.flowPublisherToFlux(provider.fetchStream(...))`
  `.publishOn(Schedulers.boundedElastic())`（把阻塞 `source.next()` 移出事件循环）
  `.map(chunk -> response.bufferFactory().wrap(chunk))` → `response.writeWith(body)`。
  `doOnSuccess`：`markUpstreamEnd` + 非固定路由 `recordSuccess`；`doOnError`：非固定且非熔断 `recordFailure`；
  `onErrorResume`：`finishOnce(false)`，若 `response.isCommitted()` 则 `Mono.error(e)`（中断连接，不改写已提交状态），
  否则 `writeError(deny(502, upstream(e)))`；`doFinally`：`finishOnce(signal==ON_COMPLETE)`。
- 字节分支：原 `fetchRawAsync` byte[] 路径完全不变。

`JdkFlowAdapter` 属 reactor-core（3.8.x 已含），无新增依赖。每块为全新堆数组包装，无池化内存复用。

### 变异自证（非空洞）

- 变异 A：`stream = false && ...`（强制字节路径）→ 2 红（streamsFileContent 单缓冲；upstreamError 200≠502），
  jsonMetadataGet 仍绿。证明流式分支确被驱动。
- 变异 B：流式 `onErrorResume` 的 `deny(502,...)`→`deny(200,...)` → 1 红（upstreamError 200≠502）。证明 502 映射被针住。
- 两次变异后均已还原；还原后重读实现确认干净。
