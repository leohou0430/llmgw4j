# 第二阶段 T2.6：临时 spool 与磁盘保护（core 纯 JDK）

日期：2026-11-14。落点：`llmgw-core/.../multipart`（SpoolLimitException / SpoolManager / Spool）。纯 JDK，无 Spring/Reactor/HTTP。本文件记录本轮实际测量，不改写历史测量。

## 交付

- `SpoolLimitException extends IOException`，`Reason { TRANSFER, TOTAL, DISK }` + `reason()`。
- `SpoolManager implements AutoCloseable`（每进程一个受限目录 + 独立配额）：
  - `Config(directory, maxTransferBytes, maxTotalBytes, diskSafetyMarginBytes)`；`defaults(dir)` = 66 MiB / 264 MiB / 64 MiB（计划 §1）。
  - 构造：`createDirectories` + POSIX `rwx------`（非 POSIX  best-effort）+ **清理上一轮遗留文件**。
  - `create()`：先查 `getFileStore().getUsableSpace() < margin` → DISK 前置拒绝；再 `createTempFile`。
  - `reserve(n)`：`addAndGet`，超 `maxTotal` → **回滚** `addAndGet(-n)` 后抛 TOTAL；`release(n)`；`totalBytes()`。
  - `close()`：CAS 幂等，删除目录内文件（best-effort）。
- `Spool implements AutoCloseable`（单传输）：
  - `write(b,off,len)`：先查单传输 cap（`size+len > maxTransfer` → TRANSFER，**不预留**），再 `manager.reserve(len)`（可能 TOTAL），写出后 `size+=len`；写失败 `release(len)` 回滚。
  - `source()`：flush 后以 16 KiB 块回放为 `ByteStream.Source`；回放完成经 ByteStream 单订阅 release → `Spool.close()`。
  - `tee(upstream)`：写穿——拉上游 chunk，`b.duplicate()` 拷贝落盘，原 buffer 重新包 `ByteChunk` 原样转发（所有权不破坏）；close 关上游 + 关 spool。
  - `close()`：**CAS 恰好一次** 关流 + `release(size)` + `deleteIfExists(path)`。结束/取消/异常都经此路径清理。

## seam 生命周期测试（`SpoolManagerTest`，@TempDir，12 测试）

defaultsHavePlanLimits（66/264/64 MiB）、writeAndReplayInBoundedChunks（40000 字节回放逐字节一致 + chunk≥2 + 完成即删 + 配额归零）、closeDeletesFileAndReleasesQuota、closeIsIdempotentAndReleasesOnce（双 close 只释放一次，配额不为负）、perTransferQuotaReject（TRANSFER 且预留为 0）、totalQuotaRejectRollsBack（TOTAL 回滚，先到者 intact）、diskMarginReject（DISK）、startupLeftoverCleanup（构造清遗留）、instanceIsolationAcrossDirectories（双目录互不影响：关一个不删另一个、配额独立）、teeWritesThroughAndCleansOnClose（每转发块即落盘 + close 清理）、cancelCleansSpool（request(1) 后 cancel → 删文件 + 配额归零）、upstreamErrorCleansSpool（上游 IOException → onError + 删文件 + 配额归零）。
