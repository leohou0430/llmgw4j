# 网关性能审查与优化

范围：当前网关转发热路径；本轮暂停身份/管理能力扩展。保留配额、租户隔离、响应大小、并发上限、SSE 错误/结束帧与取消语义。

1. 冻结当前 JAR 为 before；用独立上游、相同 Docker CPU/堆限制、唯一请求和真实计数建立反馈环。
2. JFR 采样 JSON/SSE 与两引擎，优先验证调度/客户端桥接、解析/复制、治理 side-car/指标竞争三个假设。采样数据只用于定位，吞吐对照另以无 profiler 运行。
3. 根据采样排序选择瓶颈，每次只改一个变量；用正确调用路径的语义测试及局部测量锁定前后行为和开销。
4. 改进候选与 before 在同一批次、相同参数运行多轮交替顺序 A/B；至少覆盖 JSON/SSE、治理 on/off。结果包含错误率、请求计数、p50/p95/p99、RPS 及范围。
5. 只有有证据的改进保留；波动或失败结果完整披露，不能通过关闭治理、调大保护边界或截断成功提速。
6. 运行相关契约和 Maven 检查，给出瓶颈、代码改动、实际收益与剩余性能限制。旧跨网关排行不与本轮 A/B 拼接。

本轮 profiling 的治理 on 指本地内存治理：不开启远程 embedder/guardrail 或 Redis 延迟。基准只调用本地 mock，不触及付费上游；不提交或发布。
