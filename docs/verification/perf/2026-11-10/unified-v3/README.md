# 统一容器代理性能实测

日期：2026-11-10。仅排名本机、固定版本和代理基线配置，不代表全市场、全功能治理或生产最大容量。

各网关 4 CPU/2GB，同一 Docker VM（16 CPU、约 19.6GiB），同一 mock 上游与公共 Nginx 静态 bearer 认证；50 VU，预热 3s，正式每轮 10s，共 3 轮，轮换顺序；无 TLS、缓存及付费模型调用。各表按 RPS 中位数降序；p99 是三轮各自 p99 的中位数，不是合并分布 p99。短闭环负载下吞吐主要随延迟变化，不能解释为饱和容量。3s 预热没有证明所有运行时都达到稳态，部分 JVM 配置首轮与后轮波动明显；不删除首轮，保留全部范围，因此排序仅是短时观察。

wire 上游延迟为 0；inference 的 JSON 为 20ms，SSE 为 20ms 首延迟加 8 次 10ms 间隔。SSE 测完整流耗时，不测首 token。完整 JSON 内容、8 个 SSE chunk 和结束帧均校验，上游实际请求数必须与客户端计数一致。任一正式轮失败即排除整个配置在该场景的排名；预热失败也明确排除，不挑选好轮。

复现命令及部署设置见 [基准说明](../../../../../bench/cross-gateway/README.md)。原始 [manifest](manifest.json)、[全部样本](samples.json)、[机器可读排名](ranking.json)、[k6 summary 与容器日志](raw/)。manifest 固定实际镜像 ID/摘要、源码校验和及候选 JAR SHA256。

## 优化前后与解释

- wire/json：WebFlux RPS 中位数变化 -8.2%。仅三轮短测量，须结合范围判断，不能把局部检查的 13 倍改善当成此处吞吐改善。
- wire/sse：WebFlux RPS 中位数变化 -18.2%。仅三轮短测量，须结合范围判断，不能把局部检查的 13 倍改善当成此处吞吐改善。
- inference/json：WebFlux RPS 中位数变化 -0.8%。仅三轮短测量，须结合范围判断，不能把局部检查的 13 倍改善当成此处吞吐改善。
- inference/sse：WebFlux RPS 中位数变化 +1.4%。仅三轮短测量，须结合范围判断，不能把局部检查的 13 倍改善当成此处吞吐改善。

相邻配置的范围重叠或中位数相差不足 5% 时，应视为接近；名次仅是本批观察顺序。延迟场景接近直接上游，说明该负载主要受模拟推理延迟约束，无法区分极小网关差距。实际模型、更大请求、TLS、更多并发或完整治理开启后须重新测量。

未经同口径测试的 Higress、Kong AI Gateway、New API、Cloudflare AI Gateway 不进入排名，也不排末位。功能、企业许可和平台运维能力另见 [功能差距报告](../../../../gap-analysis.md)。

前两批 `unified` / `unified-v2` 因连接关闭导致预热/控制组失败而停止，不能与本批拼接。当前批次统一提高模拟上游连接接收队列、空闲连接上限与空闲超时，开启 TCP_NODELAY 并记录失败响应；所有参赛者使用同一新 fixture。失败不解释为产品永久缺陷，复现原因与资源设置应一并评估。
