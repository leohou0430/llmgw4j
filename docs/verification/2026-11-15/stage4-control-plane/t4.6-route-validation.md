# T4.6 路由发布接入结构化配置校验（运行时）

- 新增 `RouteCandidateValidator`（control-default）：把管理 API 的 `upstream` map 转为 `UpstreamCandidate` 并调用 `DefaultConfigValidator`；缺失/类型错误也返回违规而非放行。
- 发布体新增可选 `upstream`：存在即校验；违规 400 并写 `route.publish.rejected` 审计；通过才保存草稿并发布。
- 平台策略 bean：`PlatformPolicy.strict()`（仅 https、禁止私网/回环/元数据地址）。
- 单测：`RouteCandidateValidatorTest` 4/4；control-default 全模块 23/23。

运行时（JAR，webflux 18150，独立库）：

| 请求 | 结果 |
|---|---|
| https + api.deepseek.com（timeout 30000/concurrency 100） | 200，version=1 |
| scheme=http | 400 |

限制：`upstream` 为可选字段；不含该字段的旧式不透明 config 仍可发布（向后兼容），来源 CRUD 未实现。
