# T4.12 Linux amd64 双引擎 native（当前源码）

本轮用**当前工作区源码**（分支 `codex/gateway-capacity-audit`，含 T4.8/T4.2/T4.11 变更与本次 AOT hint 修复）在 Linux 容器内重新构建 WebFlux 与 VT 两个 native 镜像，并各自运行控制面 HTTP 检查。不调用付费供应商，不测性能/SLO，不提交或推送。

## 环境与输入

- 镜像 `llmgw-native-audit:linux-20261111`：Ubuntu 26.04.1 / glibc 2.43，Oracle GraalVM 25.0.4（`/opt/graalvm`），Maven 3.9.16（`/opt/maven`）。
- 构建容器 12 CPU / 16 GiB，禁 swap；同一时间只跑一个 native 构建。运行容器 4 CPU / 4 GiB。
- 源码基线：`main` @ `88e460f`，工作区含未提交的 T4.8/T4.2/T4.11 变更与本次 hint 修复；快照 2,966 个文件，整体摘要 `0b8f4a9a746c40d9b9de64bf68b21890ef94ac6871810e27ca762fd82af35580`。
- 源码为精简副本 `/tmp/llmgw-native-src`（排除 `.git`、`target`、`bench`、`bin/native`），以只读方式把 `bin/native` 挂入运行容器；每次运行使用全新的 `LLMGW_CONTROL_DB` 与随机 32 字节 `LLMGW_ROOT_KEY`（仅保存在本机临时目录，未入库）。
- 首管理员由 `LLMGW_ADMIN_USERNAME` / `LLMGW_ADMIN_PASSWORD` 注入，无默认凭据。

## WebFlux

### 首次构建发现真实缺口

第一次构建（sha256 `423e1ce4…`，302,188,800 bytes）启动正常（`Started … in 0.396 seconds`），但控制面检查暴露两处 native 专属 500：

- `GET /control/audit` → `com.oracle.svm.core.jdk.UnsupportedFeatureError: Record components not available for record class io.github.leohou0430.llmgw.app.AuditLog$Entry`（Jackson 3 调用 `Class.getRecordComponents()`）。
- `GET /control/tenants`、`GET /control/projects` → 同类失败，缺 `OrgStore$Tenant` / `OrgStore$Project` 的 record 反射注册。

修复：在 `GatewayRuntimeHints` 注册 `AuditLog.Entry`、`OrgStore.Tenant`、`OrgStore.Project` 全部 `MemberCategory`，与既有控制面 record（`SecretSummary` 等）一致。

### 重建后的结果

- 产物：`bin/native/llmgw-webflux`，302,188,800 bytes，sha256 `c8d48836d7069f242e2faf8f99200f699dfd500e5340814ca512afe5671b3222`（stripped ELF 64-bit x86-64，动态链接）。
- 启动：`Started LlmGatewayApplication in 0.179 seconds`（profile `webflux`，Netty 监听 18080）。
- 30 项 HTTP 检查全部 PASS：
  - health 200；登录 200（会话 Cookie + CSRF）。
  - 建 key 返回一次性 `plaintext` 与 `sk-****…` 掩码；列表无明文。
  - 非法 upstream（仅 `baseUrl`）400；合法 `name/scheme/host` 发布 200，`version=1`，`/control/routes` activeVersion=1。
  - catalog 建/列 200，条目 `native-res`。
  - 租户/项目建与列表 200（修复前为 500）。
  - 密钥加密创建 200，列表掩码 `****3456`。
  - `/control/audit` 200，包含 `key.create`/`route.publish`/`catalog.create`/`secret.create`；租户/项目审计行按 `project_id=t9` 直接查库确认。
  - logout 200 后 `/control/keys` 401（`/control/status` 本身是公开的不变量端点，不用于断言会话失效）。
  - `schema_version=max=6`，`PRAGMA integrity_check=ok`。
