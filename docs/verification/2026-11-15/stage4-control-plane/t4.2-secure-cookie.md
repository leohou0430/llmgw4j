# T4.2 控制面 Secure Cookie 可配置（2026-11-16）

补齐审计发现的“会话 cookie 的 `Secure` 硬编码为 false”：登录/登出 cookie 的 `Secure` 属性改由配置决定，TLS 部署可开启。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `gateway.control-cookie-secure`（`LLMGW_CONTROL_COOKIE_SECURE`） | `false` | 为 `true` 时 `llmgw_sid` 的登录与清除 cookie 均带 `Secure` |

纯 HTTP 本地运行保持默认 `false` 以免浏览器拒收 cookie；任何 TLS 终止（网关自身或前置代理）部署应设为 `true`。

## 行为

- 登录 `POST /control/login` 与登出 `POST /control/logout` 使用同一配置值；`HttpOnly`、`SameSite=Lax`、`Path=/control` 不变。
- 登出清除 cookie 的 `Secure` 与登录时一致，避免属性不一致导致残留。

## 测试（新增 4，全绿）

`ControlLoginControllerCookieTest`：

| 测试 | 断言 |
| --- | --- |
| localDefaultKeepsCookieNonSecure | 默认无 `Secure`，同时含 `HttpOnly`/`SameSite=Lax`/`Path=/control` |
| tlsDeploymentMarksCookieSecure | 配置 true → 含 `Secure` |
| logoutClearsCookieWithConfiguredSecureAttribute | `Max-Age=0` 且 `Secure`/`HttpOnly` 一致 |
| loginReturnsSessionBoundCsrfToken | 登录返回 `csrfToken` |

命令：`mvn -o -B -pl llmgw-core,llmgw-app -am test -Dtest='ControlLoginControllerCookieTest,GatewayPropertiesAdminTokenTest' -Dsurefire.failIfNoSpecifiedTests=false` → BUILD SUCCESS（4 + 3，0 失败）。
