# T4.11 磁盘满、SIGKILL 断写与根密钥恢复（2026-11-16）

补齐 T4.11 未测项：真实 `ENOSPC`、进程强杀后的数据库一致性、备份还原后的根密钥语义。

## 实现变更

| 变更 | 说明 |
| --- | --- |
| `LLMGW_CONTROL_DB_MIN_FREE_BYTES` | 最小剩余空间阈值可配置（默认 256 MiB，原硬编码），便于受限卷与故障注入验证 |
| `SqliteErrors.isStorageFull` + `StorageLimitException` | 密钥、路由版本、租户/项目、账号、会话的写入在驱动报 `SQLITE_FULL`/`database or disk is full` 时抛出容量异常，而非归类为参数/内部错误 |
| `StorageLimitAdvice` | 所有 `StorageLimitException` 统一 503；路由发布 `tryConflict` 不再把容量异常改写成 400 |
| `RootKeyMismatchException` | 根密钥与库内密文不匹配时 fail-closed：列表、创建、轮换均 503，且不写入用错误密钥加密的新数据 |

## 运行时：SIGKILL 断写（webflux）

对同一控制库连续 3 轮：登录 → 并发写入密钥 → 随机 30–150 ms 后 `SIGKILL -9` → 重启。每轮断言 `integrity_check=ok`、行数单调不减、行数覆盖已确认成功数；最终列表可解密全部 12 行。全部 PASS。

说明：这是进程级强杀的一致性验证，不是硬件掉电/扇区级部分写实验。

## 运行时：真实磁盘满（Linux 容器，双引擎）

镜像 `llmgw4j:v13-test`（Temurin 25.0.5），控制库放在 `--tmpfs /data:size=4m`，启动后写满该卷（`df` 可用 0 KB）。

| 引擎 / 余量阈值 | 密钥写入 | 路由发布 | 密钥读取 | 行数 | 路由读取 |
| --- | --- | --- | --- | --- | --- |
| webflux / 0（绕过 guard 余量，直达 SQLite `SQLITE_FULL`） | 503 | 503 | 200 | 不变（1） | 200 |
| vt / 0 | 503 | 503 | 200 | 不变（1） | 200 |
| webflux / 1 MiB（guard 余量路径） | 503 | 503 | 200 | 不变（1） | 200 |

写入被拒绝且无部分提交，读取仍可用；容器在每轮后 `docker rm -f` 清理。
