# T2.10 2C2G 容器文件压力（双引擎实测）

日期：2026-11-15。子计划 `docs/plans/2026-11-13-stage2-files-bounded-streaming.md` T2.10。任务 #102。
脚本：`bin/stress-files-container.py`。原始数据：`t2.10-container-stress-webflux.json` / `t2.10-container-stress-vt.json`（同目录）。

## 1. 部署口径（当前代码，非历史产物）

- 运行镜像：仓库运行镜像 `llmgw4j:v13-test`（Temurin **25.0.5** JRE，entrypoint `java $JAVA_OPTS -jar /app/llmgw.jar`）。镜像 Id 记录于 JSON。
- 被测 JAR：`llmgw-app/target/llmgw-app-0.3.1.jar`，**本轮从当前源码离线重建**（`mvn -o package -DskipTests -pl llmgw-app -am`，含 T2.8 fetchStream 空闲看门狗生产改动），以只读卷挂载到 `/app/llmgw.jar`。sha256 前缀 `3f9c018a339ce71b`（完整值见 JSON）。
- 资源硬限：`docker run --cpus=2 --memory=2g --memory-swap=2g`（**禁 swap**，超限即 OOM-kill）。发布 `127.0.0.1:18080→8080`。
- 关键配置（`SPRING_APPLICATION_JSON`）：`max-request-bytes=80MiB`（整体 multipart 上限；每文件仍默认 64MiB）、`max-concurrent-requests=4`、治理**启用**但 quota/rate/burst 提至 2e9（字节上传按 totalBytes/4 计 token，默认 burst 200000 会 429；提高阈值以**隔离传输/spool/并发**行为，非关闭治理）。`JAVA_OPTS=-Xmx1g -XX:MaxGCPauseMillis=10`。
- 上游：进程内 mock（port 9090），provider 走**真实 jdk-http HTTP**（gateway→mock 回环），`/mock/v1/files` 处理 multipart 上传。非真实 DeepSeek（凭据门控，见 §5）。

## 2. 工作负载

4 路并行 64 MiB multipart 上传（慢写：256KiB/块、10ms 间隔，持有许可约数秒）+ 并发管理 GET（`/admin/snapshot`、`/admin/metrics`、`/admin/routes`）；饱和期第 5 路上传；中途取消（发送 8MiB 后 RST 断连）；恢复上传。`docker stats` 采样 RSS/CPU；`docker exec` 核查 spool 目录文件数；`docker inspect` 核查 OOMKilled/Status。

## 3. 实测结果（16 项断言全 PASS，两引擎）

| 断言 | WebFlux | VT |
|---|---|---|
| 4×64MiB 上传 | 4×200 | 4×200 |
| 饱和第 5 路 | 503 | 503 |
| 管理并发响应 | 48/48×200 | 58/58×200 |
| 压力中 spool 文件 | 4 | 4 |
| 上传后 spool 清理 | 0 | 0 |
| 取消中止 | RST aborted | RST aborted |
| 取消后 spool 清理 | 0 | 0 |
| 取消后许可归零→恢复 | 200 | 200 |
| 恢复 64MiB 上传 | 200 | 200 |
| 恢复管理 | 200 | 200 |
| 终态 spool 空 | 0 | 0 |
| **峰值 RSS** | **890.0 MiB / 2048** | **795.3 MiB / 2048** |
| **峰值 CPU** | **200.4%** | **93.5%** |
| OOMKilled | false | false |
| 容器状态 | running | running |

- WebFlux 峰值 RSS 933232640 B（890.0 MiB），Phase A 时长 11.66s；CPU 200.4% ≈ 2 核饱和。
- VT 峰值 RSS 795.3 MiB；CPU 93.5%（VT 单上传较慢、并行 CPU 占用较低）。
- 两引擎 RSS 均**远低于 2GiB 硬限**（余量 >1.1GiB），无 OOM，spool 终态归零，取消后许可恢复。

## 4. 测量口径与局限（如实）

- `docker stats --no-stream` 单次约 1–2s 延迟，每轮仅采到 **5 个样本**；峰值取样本最大值，可能略低估瞬时峰值，但 RSS 距 2GiB 余量充足，结论稳健。
- CPU% 相对宿主核数；200% 对应 2 核限额饱和。
- mock 上游与 gateway 同进程，mock 侧缓冲上传体属测试夹具开销，已计入容器 RSS；gateway 侧客户端→spool 为磁盘有界（堆平稳）。
- 治理阈值提高是为隔离资源行为；治理+许可交互的语义正确性由 T2.7 双引擎单测承担。
