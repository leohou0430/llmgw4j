# T2.4 WebFlux 上传流式桥接线（任务 #98）

日期：2026-11-15。阶段 2 Files 有界流式。引擎：engine-webflux（HTTP 豁免模块）。镜像 VT #97。

## 接缝（事先约定）

1. `WebfluxGatewayController.handleFileUpload / handleTranscriptions → handleUpload → forwardUpload`：
   客户端 `Flux<DataBuffer>` 经 `DataBufferBodySource`（push→pull 桥）→ `MultipartUpload.prepare`（扫描+spool）→ 冷 `ByteStream` 逐块 `provider.fetchRawAsync(EngineRoutes.postRawBytes(...))`。替换原 `DataBufferUtils.join` 整体缓冲。
2. `DataBufferBodySource`（新，webflux 包内）：`publishOn(boundedElastic, prefetch=1)` + 容量 4 的 `ArrayBlockingQueue` 交接；每块复制后立即 `DataBufferUtils.release`，再 `request(1)`；错误转 IOException、EOF 哨兵、close() CAS 一次取消订阅并唤醒阻塞的 next()。阻塞交接全部在 boundedElastic，绝不占事件循环。

## 实现要点

- 每控制器惰性 `SpoolManager`（`llmgw-webflux-spool-` 临时目录 + `Config.defaults`），`implements AutoCloseable`，Spring 推断销毁调用 close()。无静态全局。
- 限额映射与 VT 一致：`Limits(64MiB, max(1, maxRequestBytes), 64KiB)`；`MultipartLimitException|SpoolLimitException → 413`，其他 IOException → 400，缺 boundary → 400。
- 路由保真：FILES=purpose / TRANSCRIPTIONS=model；FILES 响应 id → taskRoutes.bind。
- 终态路径：`forwardUpload(...).doFinally(prepared.close())` 覆盖成功/拒绝/上游错误/取消；prepare 失败在 fromCallable 内 catch 关闭 source；治理 finish 仅建立 context 后调用（finishOnce 幂等）。
- `prepared.body()` 抛 IOException，在 Mono.defer 内捕获转上游错误信号（502），不污染事件循环线程。
