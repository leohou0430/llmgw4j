## 2. 生产改动

两引擎 `handleUpload` 顶部新增前置 413（读体/订阅体之前）：
- VT `VirtualThreadGatewayController.java:503`：`long declared = request.getContentLengthLong(); if (declared > properties.getMaxRequestBytes()) → 413`，位于 `requestSlots.tryAcquire()` 之前（超限不占许可）。
- WebFlux `WebfluxGatewayController.java:1035`：`long declared = request.getHeaders().getContentLength(); if (declared > ...) → 413`，位于 `new DataBufferBodySource(request.getBody(), ...)` 之前（超限不订阅体）。
- 未知长度（-1）不触发前置检查，落到既有扫描器累计上限（T2.5/T2.6 已具备）。
- 许可释放：VT `handleUpload` finally `requestSlots.release()`（#97 已就位）；WebFlux 租约在 `WebfluxCapacityAdmission.filter` doFinally 释放一次（既有）。

## 4. 变异自证（每个变异精确杀死目标测试，随后还原）

- **变异 A**（VT 前置 413 禁用：`if (false && declared > ...)`）→ `vt.knownLengthOverCapIs413WithoutReadingBodyOrTakingPermit` 红：`expected: <413> but was: <200>`（体被读取、小体未超限被放行）。还原。
- **变异 B**（WebFlux 前置 413 禁用）→ `webflux.knownLengthOverCapIs413WithoutSubscribingBody` 红：`a declared over-cap length must be rejected before the body is subscribed ==> expected: <false> but was: <true>`（体被订阅）。还原。
- **变异 C**（VT 许可释放禁用：finally `if (false) requestSlots.release()`）→ `vt.fourParallelUploadsShareTotalConcurrencyAndReturnPermits` 红：`permits must return to zero after parallel uploads complete ==> expected: <200> but was: <503>`（许可泄漏）。还原。

三处变异还原后 `grep "if (false"` 两控制器无残留。
