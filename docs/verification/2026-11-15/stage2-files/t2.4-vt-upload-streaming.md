# T2.4 VT 上传流式桥接线（任务 #97）

日期：2026-11-15。阶段 2 Files 有界流式。引擎：engine-vt（HTTP 豁免模块）。

## 接缝（事先约定）

`VirtualThreadGatewayController.handleFileUpload / handleTranscriptions → handleUpload → handleUploadWithinCapacity`：
客户端 multipart 经 `ByteStream.inputStreamSource`（16KiB 有界读）→ `MultipartUpload.prepare`（扫描+spool，scan-first）→ 冷 `ByteStream` 逐块转发 `provider.fetchRaw(EngineRoutes.postRawBytes(...))`，不再整体缓冲 byte[]。

## 实现要点

- 每控制器惰性 `SpoolManager`（`Files.createTempDirectory("llmgw-vt-spool-")` + `Config.defaults`），镜像 `requestSlots` 的实例所有权；控制器 `implements AutoCloseable`，`close()` 关闭 manager 并删除临时目录（Spring 推断销毁方法）。无静态全局。
- 限额映射：`Limits(maxFileBytes=64MiB, maxMultipartBytes=max(1, properties.maxRequestBytes), maxMetadataBytes=64KiB)`；`MultipartLimitException|SpoolLimitException → 413`，其他 `IOException → 400`，缺 boundary → 400。
- 路由保真：FILES 取 `purpose` 字段、TRANSCRIPTIONS 取 `model` 字段（对齐 DefaultProtocols.Multipart）；FILES 响应解析 `id` 后 `taskRoutes.bind`。
- 所有终态路径（成功/治理拒绝/上游错误）`prepared.close()` 恰好一次 + 外层 finally `requestSlots.release()`；治理 finish 仅在建立 context 后调用。
