# 本轮 2C2G 容量与性能复验

第1步收尾已完成。当前WebFlux native构建与功能契约通过，见[单独记录](final-native.json)；本文件的CPU/容量数据仅属于JVM/容器实验。

新产物 `idle-output.jar` SHA256 `34425d57569f47690b11dd6748d1410477076dd2f442f8c55323ff3e829a9482`；比较基线为上一轮EOF候选（不是发布版本），SHA256 `0485fc98599c117939b8ea0b5cf00e4ecacd1abc1f1b55b813629eef5fe191a5`。两边均为原生SPI/Flow实现，不隔离v0.3.1相对旧Reactor桥的成本。

## 固定资源与方法

每个被测网关独立容器、2CPU/2GiB、1GiB Java堆、无swap、1实例。本地受控上游另容器，不访问供应商。默认本地治理，唯一请求避免精确缓存命中；JSON延迟20ms，SSE 8个数据片段、间隔10ms。64/96 VU，三轮每轮6秒，64VU预热5秒，偶数轮反转候选顺序，客户端遵循Retry-After。CPU比较期间未同时运行Maven/native。

[原始汇总](final-capacity-summary.json)由 `bench/results/lifecycle-2026-11-11/final-capacity/` 的完整manifest/samples/k6/cgroup/日志生成。62个样本含48个正式比较、8个预热、2个直连见证、4个长流；全部k6无意外失败。新候选正常完成均无上游取消，拒绝请求没有到达上游，退避数与容量拒绝数一致，JVM/cgroup未发现OOM。长流为每候选/引擎32客户端约30秒，均完整交付8片段和[DONE]。

## 64VU比较（三轮中位数）

64是当前准入上限，不是无拒绝SLO。WebFlux JSON基线/新候选三轮共5/2次容量拒绝，分别统计；其余下表场景无拒绝。成功吞吐不包含503，CPU/成功响应包含采样区间内的拒绝与清理工作。p99口径是各轮p99的中位数，不是合并分位数。

| 引擎/模式 | 成功响应/s before → after | 容器CPU ms/成功响应 before → after | HTTP p99 ms before → after |
|---|---:|---:|---:|
| webflux/json | 988.7 → 973.7 | 2.129 → 2.134 | 109.90 → 108.36 |
| webflux/sse | 570.0 → 556.7 | 1.577 → 1.471 | 123.85 → 129.44 |
| vt/json | 1488.0 → 1436.1 | 1.373 → 1.408 | 79.86 → 84.43 |
| vt/sse | 577.6 → 571.7 | 1.484 → 1.435 | 122.06 → 122.75 |

SSE每成功响应CPU中位数较基线下降约6.7%（WebFlux）/3.3%（VT）；JSON为约+0.2%/+2.5%。成功吞吐中位数均有小幅下降，HTTP尾延迟也有混合变化；三轮短批次不支持全面或稳定提速结论。主要确定收益是修复大帧非线性解码、慢读OOM与超时/取消缺陷，不能把局部解码提速当成整网关倍率。96VU的完整拒绝、退避、成功及CPU结果保留在JSON，不把快速503算容量提升。

## 64慢读与大帧（独立实验）

每响应提供约64MiB、每行接近1MiB既有上限，接收缓冲请求1KiB、每0.5秒读64字节、持续45秒；客户端响应头是绝对10秒预算。[完整汇总](idle-slow-summary.json)的四组均64/64、关闭后upstream active0/cancelled64、恢复200，无OOM。

| 引擎 | 心跳ms | 最大响应头ms | cgroup内存峰值MiB |
|---|---:|---:|---:|
| webflux | 0 | 4607 | 1254.4 |
| vt | 0 | 5346 | 887.7 |
| webflux | 40 | 2222 | 1216.9 |
| vt | 40 | 1932 | 874.1 |

原始JDK路径的同类10秒批曾4/64超时；快速解码中间候选又暴露30秒cgroup OOM，均保留在[总报告](README.md)，未放宽预算或降低合法行上限掩盖失败。

局部解码探针中，16KiB→约1MiB（约64倍字节），旧JDK当前线程CPU中位数0.135→369.2ms（约2741倍），新解码0.0444→2.953ms（约66.5倍），见 `jdk-line-scaling.jsonl` 与 `idle-line-scaling.jsonl`。探针不包含完整网关和全部GC成本，不是生产吞吐收益。

出口仍按行分配UTF-8字节数组，8KiB是可读分片上限，分片可能共享整行的背衬数组；低行预取限制同时保留的大行数，并非零拷贝或逐字节编码。
