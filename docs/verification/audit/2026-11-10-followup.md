# 产品核对与性能打磨实施记录

本轮承接前一轮全仓审查，目标为源码反向核对主流网关能力，修复已有能力的实际问题，并重新建立同环境性能证据。

## 已实施及证据

- Redis `TokenLimiter` 之前未覆盖带速率/容量的四参方法，模型策略退回全局默认。真实 Redis 两个实例先复现“模型小桶未限制、退款容量错误”，再覆盖方法并在 Lua 保存/使用桶容量。见 [RED](2026-11-10-evidence/redis-red.log)、[GREEN](2026-11-10-evidence/redis-green.log)。
- 治理结算之前只处理 key 限流桶，模型桶在失败/缓存路径不退款；成功差额调用也可能恢复全局桶形状。新增三项测试先失败，再补齐同一模型参数的结算。见 [RED](2026-11-10-evidence/model-rate-red.log)、[GREEN](2026-11-10-evidence/model-rate-green.log)。此处修复 token 速率额度，不代表新增持久化金额账本。
- 资源归属检查增加普通文本安全快速路径；任何 `file_id` 字样或 Unicode 转义仍建树检查。嵌套、Unicode 绕过和普通文本边界三项回归通过。见 [语义回归](2026-11-10-evidence/ownership-tests-green.log)。
- 4KB 文本、同一 JVM 参数和微基准、丢弃首轮后的七轮中位数：该检查线程 CPU 3728.06ns→280.50ns；线程分配 5816B→0B。见 [前](2026-11-10-evidence/ownership-before.csv)、[后](2026-11-10-evidence/ownership-after.csv)；源码 `bench/micro/ResourceOwnershipMicrobench.java`。仅检查本身，不推导整服务倍数。
- CI/release 加真实 Redis service；CI 加基准分析器与 mock 消费者契约测试。功能差距及官方来源见 [更新后的功能报告](../../gap-analysis.md)。

## 性能证据要求

全部产品在同一 Docker VM，网关 4 CPU/2GB、相同独立上游、同一 Nginx bearer 认证、同一 k6 脚本。JVM 与 Python/Go/Node 的差异不能被用来猜测未经测量的排行。版本和摘要、资源、配置、预检与原始结果由 runner 记录。

`unified` 首次运行在 Bifrost wire JSON 预热中发现 2/14286 失败（两请求未达上游），中止，没有生成正式排行。之后为所有配置统一提高 mock 接收队列、记录失败响应，测试器允许某配置失败后继续测其他配置，但失败配置在对应场景排除，不删除坏轮。完整 JSON 内容与全部 SSE chunk 也加入成功校验。第二批 `unified-v2` 在 Bifrost/旧 WebFlux 预热及直接上游控制组也发现关闭连接导致的失败，停止，不生成结论。JDK HTTP server 默认空闲连接上限 200、超时 30s；第三批统一设置 10000/1800s 并开启 TCP_NODELAY，降低共享 fixture 在轮换期间淘汰连接及 Nagle 延迟的干扰。正式批次为 `unified-v3`，不得从前三批拼接或挑选最好成绩。

未调用真实付费上游，未执行远端 CI、提交、推送或发布。长期压力、TLS、真实模型首 token、完整治理功能成本不在本次代理基准范围。

## 最终实测结果

- [统一容器主测](../perf/2026-11-10/unified-v3/README.md)：84 个样本，全部零错误、上游计数一致。JSON/SSE、wire/inference 分别排名，不推导全市场名次。
- [独立 WebFlux A/B](../perf/2026-11-10/webflux-ab/README.md)：长预热、四轮顺序轮换，8 个样本全部通过；中位数 3602.8→3834.6 RPS（+6.4%），范围重叠。主测短预热方向相反，不宣称稳定整服务增益。
- README、历史性能文档及旧报告增加撤回/历史范围说明，当前入口指向新结果。
