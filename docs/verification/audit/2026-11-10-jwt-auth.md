# JWT 身份边界与认证开销增补

本轮继续处理身份能力缺口：补充 HS256 接收方限制，修复已存在的声明校验错误，并移除每次校验重复创建 JSON mapper 的开销。没有增加 OIDC discovery、JWKS 或企业身份平台。

## 复现、修改及兼容范围

- 旧实现把非数值 exp/nbf 当作未提供，导致无效时间声明被接受；新实现对存在的时间声明要求 NumericDate，支持小数秒精度。
- 旧实现允许到达 exp 的 token；新实现到达该瞬间即拒绝，nbf 则在到达时允许。以固定 Clock 验证边界，不依赖测试执行是否跨秒。
- 旧实现可能把非对象 claims 映射为匿名身份，并把数字 iss/sub 转成字符串；新实现要求 claims 为对象、存在的 iss/sub 为字符串。
- 旧 split 丢弃末尾空段，接受多余点号；新实现要求恰好三个紧凑序列段。
- 新增 `gateway.auth.jwt-audience`：配置后必须匹配 aud 字符串或全字符串数组，区分大小写；缺失、错误及混合类型数组拒绝。默认空保持未配置受众约束的兼容行为。
- exp/nbf 仍可缺失；缺失或空白 sub 仍映射 `jwt:anonymous`。不提供时钟偏移宽限。算法仍仅 HS256，静态 key 认证不受影响。

规则依据：[RFC 7519 的 audience 与 NumericDate 时间声明](https://www.rfc-editor.org/rfc/rfc7519.html#section-4.1.3)。这只是相关声明约束，不声称实现所有 JOSE/OIDC 策略。

## 性能验证

JWT 头部和声明共用不可变 JSON mapper，HMAC 状态仍按调用独立创建；未跨线程复用可变 Mac。[Jackson 3 官方线程安全说明](https://github.com/FasterXML/jackson-databind/blob/3.x/src/main/java/tools/jackson/databind/ObjectMapper.java)支持这种 mapper 复用方式。

同一已签名有效 token、相同 JVM 参数，完整校验微基准共 6 轮，每轮 10000 次，首轮预热不计，保留其余 5 轮。线程 CPU 中位数 **9903.20ns→4084.40ns**；线程分配中位数 **50648.59B→4514.75B**。包含新声明校验成本；这是局部线程测量，不代表整网关吞吐或端到端时延收益。

源码：`bench/micro/JwtValidationMicrobench.java`；[优化前](2026-11-10-jwt-evidence/before.csv)、[优化后](2026-11-10-jwt-evidence/after.csv)。运行类路径由 core/default 两模块的 target/classes 和应用依赖组成；参数 `-Xms256m -Xmx512m`，无网络和付费上游。
