# 管理鉴权边界增补

本轮承接产品差距报告中的管理权限缺口，修复现有双凭据授权的实际错误；没有扩展只读凭据权限，也没有把两个静态 token 描述为完整 RBAC。

## 复现与根因

1. 完整管理 token 非空、请求不带审计凭据时，`isReadAuthorized` 对 null 调用 `getBytes`，审计接口返回 500，而不是 401。
2. 仅设置审计只读 token 时，审计判断和 `requireAdmin` 都仅检查完整 token 是否为空，误进入开放演示模式。旧 JAR 的 HTTP 探针实际得到匿名 `DELETE /admin/cache` 200，构成写权限绕过。
3. 生产配置允许完整与只读管理凭据相同，使持有只读凭据的调用者同时具有完整权限。

[控制器失败测试](2026-11-10-admin-auth-evidence/auth-red.log)、[生产配置失败测试](2026-11-10-admin-auth-evidence/config-red.log)、[旧产物 HTTP 复现](2026-11-10-admin-auth-evidence/http-red.log)。旧产物是前轮保留的不可变 JAR，SHA256 见前轮基准 manifest 的 `before_jar_sha256`。

## 修改后的行为

| 配置 | 匿名审计导出 | 审计只读凭据 | 其他管理数据和写接口 |
|---|---|---|---|
| 完整和只读凭据都为空 | 允许（仅本地演示） | 无需凭据 | 允许（仅本地演示） |
| 仅只读凭据 | 401 | 仅审计导出允许 | 全部 401 |
| 完整凭据已配置 | 401 | 仅审计导出允许 | 要求正确完整凭据 |

- 共用空值安全的常数时间凭据比较；没有完整管理凭据时，只有两种凭据都为空才开放演示模式。
- 生产要求完整凭据非空，读写凭据不同；重复凭据在 Spring 配置初始化阶段拒绝启动。
- `/admin/console` 静态页面仍可匿名加载，页面的数据请求仍按上述规则授权。
- 文档同步：SECURITY、配置说明、用户指南、OpenAPI。CI/release 加入双引擎真实 HTTP 探针。

## 验证与范围

- 新增控制器 6 项测试，包含所有现有非审计管理端点的缺失/错误/只读凭据矩阵、完整凭据可写及拒绝写入无副作用；生产配置增加 2 项测试。针对性共 14 项通过。
- `mvn -B clean verify`：105 项发现，103 项执行通过、0 失败、0 错误；2 项真实 Redis 集成测试因本轮未提供 Redis 环境而跳过。上轮真实 Redis 通过记录仍保留，本轮未重跑该集成。
- `python3 bin/smoke-admin-auth.py`：分别在 WebFlux/VT 运行完整保护、仅只读、无凭据演示三种实例，验证 HTTP 状态及有效凭据操作；进程、临时工作目录均由探针清理。
- [新产物 HTTP 结果](2026-11-10-admin-auth-evidence/http-green.log)、[全量 Maven](2026-11-10-admin-auth-evidence/full-verify.log)、[机器可读记录](2026-11-10-admin-auth-verification.json)。
