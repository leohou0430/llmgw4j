# 主流网关对比与性能复测计划

目标：从当前代码反向确认产品差距，实施有证据的功能及性能修复，最后给出可复现的同环境性能排行。

1. 对照官方资料核查 LiteLLM、Bifrost、Portkey、Higress、Kong、New API、Cloudflare 的能力；区分开源、自托管与商业/托管能力，保留来源链接和采集日期。
2. 以源码及实际请求为证据，重新建立本项目能力矩阵。已发现 Redis 的 per-model 限流参数丢失，先用真实 Redis 失败测试复现，再修复并加入 CI。
3. native 构建在独立临时副本运行，防止 AOT 污染用于 JVM 复测的产物。构建成功后运行契约测试，不仅检查进程能启动。
4. 重建跨网关测量：所有被测网关在同一 Docker VM、相同 CPU/内存限制、相同容器网络中；使用同一个独立 mock 上游和 k6 请求。公共 Nginx 层执行同一静态 bearer 认证，代理基线关闭可关闭的治理、缓存、重试与日志。额外的治理功能单独披露，不能伪称各网关拥有完全相同的功能成本。
5. 预检要求成功 JSON、完整 SSE、错误凭据被拒；先预热，再多轮轮换顺序运行。测试 0ms wire 与带固定上游延迟两种场景，分别排名，记录版本/镜像摘要/资源/错误率/p50/p95/p99/RPS。失败或未完成同口径测量的产品不进入排行。
6. 本项目性能改进需在同一批次与保存的修复前产物对照；不能通过关闭隔离、费用保护或伪造成功来提速。
7. 更新 docs/gap-analysis.md；旧版混合实测、厂商声明和语言推断的排行保存在 archive 并明确失效。最终报告提供原始数据、运行命令、适用边界以及待做功能。

不调用真实付费供应商，不推送或发布，不操作用户其他容器。所有验证资源采用唯一名称并清理自身容器/网络。
