# 单机团队与商业网关详细设计

日期：2026-11-17。基线：v0.4.0 / `53a27d81801ca1addcae16ba0d862bbbae6c2866`。
状态：产品范围及D1–D6收费规则均已确认；以下技术架构供计划审阅，尚未实施，不代表已有功能或验证结果。

## 1. 目标与约束

同版本在单Java进程、SQLite、2CPU/2GiB下交付内部团队、企业共享和平台代管商业运营功能。单机角色不意味着单租户。继续内置账号、会话、CSRF与scope RBAC，外部客户只领取Key。首版无集群、OIDC、客户门户、自助注册、在线支付、Gemini Live或全协议两两转换。

依据：[范围及调研](../../reviews/2026-11-17-current-state-and-peers.md)、[单机ADR](../../adr/0006-single-node-feature-delivery-before-clustering.md)、[计费ADR](../../adr/0007-tenant-prepaid-billing-with-estimated-reservations.md)、[Gemini ADR](../../adr/0008-gemini-http-and-bounded-chat-conversion.md)。领域词汇保持在根目录CONTEXT.md，技术设计不写入词汇表。

基础能力不得引用Spring、Boot、Reactor；HTTP适配仅位于app及两个引擎。命名ExtensionModule显式组装，每个ExtensionContext拥有状态、调度器及资源；基础jar启用原生边界Enforcer。正常完成不得取消HTTP transport；首字节、空闲、整体期限与流完整性继续独立。

## 3. 模块与依赖建议

新增`llmgw-billing/`聚合parent，children为唯一`llmgw-billing-api`与`llmgw-billing-sqlite`。api只依赖core及必要JDK类型；实现依赖api与persistence-api。业务合同、单位校验与价格计算放api独立包，避免不必要的第三个实现模块。金额域不依赖governance-default或HTTP。

新增`llmgw-recording/`聚合parent，children为`llmgw-recording-api`、`llmgw-recording-local`；local实现使用实例独占分块目录与persistence-api保存索引。仅在local模块内部提供文件实现，不让api暴露SQLite连接、HTTP正文或Reactor类型。

在现有聚合内增加`llmgw-conversion-gemini`、必要的通用`llmgw-conversion-openai-chat`上游实现、`llmgw-provider-gemini`认证/路径能力。codec实现分别依赖conversion-api，不互相依赖；与JDK transport组合，不创建第二套HTTP客户端。

app中的`BillingRuntimeModule`、`RecordingRuntimeModule`加载到既有原生图，HTTP仅导出实例。管理控制器拆为计费、价目、正文查询三个职责，复用ControlAccess和授权动作。未来集群需整体适配存储、原子准入、路由版本与目录来源；本次不提前引入分布式锁或外部数据库。

## 4. 金额与计价合同

### 4.1 身份和计价证据

- `callId`：网关内部生成且持久化的逻辑调用标识；客户端requestId只用于关联。
- `attemptId`：callId下的真实上游尝试；每次可能产生独立采购成本。
- `operationId`：平台充值、冲正、核对等操作防重标识；同标识不同内容拒绝。
- `priceVersion`：准入时冻结的对外模型、协议/操作、单位、维度、币种、单价和生效版本。
- `usageEvidence`：原始usage证据、来源供应商/模型、是否权威、覆盖范围和采集时间。原始重叠统计不能直接相加。

已确认D2：金额以定标整数表示，账户币种仅CNY，入账单位为0.000001元（小数点后6位）。计算使用受检整数或BigInteger中间量，不用float/double，不重解释旧micro-USD字段。准入估算预留向上取整；最终合并本次全部计价项和该租户持久尾数，只将完整单位入账并保留剩余尾数，不逐流式片段取整。尾数与消费/余额投影同事务，归档、恢复和冲正不丢尾数。明确免费调用不消费或触发历史尾数入账。

算例：每个计费调用产生0.0000006元，第一次入账0元、尾数0.0000006元；第二次入账0.000001元、尾数0.0000002元。两次调用的入账金额加尾数恰为0.0000012元。期间穿插缓存免费调用不改变二者。尾数是尚未形成完整入账单位的累计费用，不是另一笔充值或可供额外调用使用的信用。

技术方案：单位价格和数量以十进制字符串输入、精确有理数参与运算，保存约分后的分子/分母，避免仅把最终long入账额留作冲正依据。对净消费变化，`whole=floor(previousRemainder + exactDeltaInMicroCny)`，新尾数为差额且落在[0,1)；余额扣除whole。冲正使用原流水精确费用的相反数并引用原记录，floor采用数学向下取整而非Java向零截断。上例冲正第一次0.0000006元时，本次入账变化为-0.000001元，新尾数0.0000006元，总净消费仍等于剩余一次调用费用。每项和聚合均检查数值/输入长度边界，不允许无界精度输入导致资源耗尽。账户投影与尾数更新同一短事务，免费调用不触发尾数变化。

### 4.2 价格和计量矩阵

| 协议 | 必须表达的量纲 | 完成与证据边界 |
|---|---|---|
| chat/responses/messages及新增Gemini生成 | 输入、输出；缓存输入、思考、工具/模态等供应商分项 | 供应商usage解释为互斥或包含关系后计价，usage缺失不自动用文本长度当权威值 |
| embeddings | 支持模型实际报告的输入单位 | 不按向量维度或返回数组长度猜token |
| rerank | 具体供应商的文档数、请求数或token等已声明单位 | 规则未覆盖的模型拒绝，不统一硬编码token价 |
| images | 张数及影响报价的模型/质量/尺寸维度 | 以完成结果和可验证数量结算，不因返回URL为空断言已免费 |
| videos | 按模型规则声明的时长/数量/规格等单位 | 创建一次预留，终态幂等结算，查询/轮询不重建计费调用 |
| audio-speech | 模型声明的字符、token或时长等单位 | 音频原件不写正文日志；单位不确定则待对账 |

已确认D6：估算器按模型和操作显式选择，不按协议名猜价格。文本输入由计量器估算；输出按请求明确的上限，未指定时要求价目版本包含模型默认输出估算值。图片/视频等要求数量、规格、时长等所需维度齐全；缺维度且无显式估算规则则拒绝。默认估算值只是预留输入，不向上游请求偷偷添加或修改输出限制；不能把它宣称为费用硬上限。模型配置同时冻结计量器版本、所需维度和默认估算参数，以便解释历史预留。

计费单位是模型规则而非协议常量。后台发布售价时必须提供单位与计量器标识并做兼容校验；明确零价有效，缺字段不是零价。禁止执行任意脚本表达式计价。定价版本已被调用引用后不可修改，改价生成新版本。

支持八类计费不表示自动抓取厂商价格、所有模型预置价格或所有附加工具费用天然已覆盖。files/batches/transcriptions以及多次调用的客户幂等约定列入D3/D4。

已确认D3：文件上传/查询/删除、任务查询等管理操作显式零价，相关上游成本由平台承担；批量模型执行、语音转写及附加付费工具独立配置计费规则，缺规则拒绝。启动执行的任务创建不是免费管理查询，按同一持久计费对象预留与结算。工具计价须声明与模型计价维度的包含关系，不将整次模型调用免费或将已包含的工具费用再收一次。零价操作仍需授权、配额/容量治理及正文记录健康检查，不成为无限资源入口。

已确认D1：网关精确/语义缓存命中时不收客户调用费，记录缓存命中和零费用，若已预留金额须幂等释放；用于语义向量等辅助上游成本由平台承担、独立归集。不得把辅助成本记作零，也不得把此规则套到供应商缓存输入的正常调用上。缓存命中仍须通过身份、scope及既有调用准入规则，不能借命中绕过授权。

### 4.3 状态机与不变量

`RESERVED → SUBMITTED → SETTLED | PENDING_RECONCILIATION`；确认从未提交可从RESERVED释放；PENDING只在核实后结算或释放。状态变更与金额流水同事务。不同业务结果与计费结果分列，不能用HTTP success布尔值决定是否零费用。

准入短事务：验证完整scope和价格 → 读余额/透支/预留投影 → 判断`balance + creditLimit - held >= estimate`及项目子限额 → 插入reservation → 增加held → 提交。所有算术检查溢出。token与金额两项准入作为一个调用协调步骤：后项失败必须幂等撤回前项；仅所有前提持久成功后才能提交上游。崩溃留下的未提交预留也不能凭进程内状态贸然退款。

结算短事务：核验单次终态与usage证据 → 按冻结售价计算实际额 → 追加账务流水 → 减held、减balance、更新项目累计消费 → 提交。实际额高于估算可形成超过透支额度的欠款，后续新调用按新可用额判断；不伪装成财务硬预算。

每次尝试独立记录成本及原币种；客户只收最终服务尝试。失败尝试成本与未知成本不能消失。上游接受异步任务后，以项目＋创建来源＋任务ID绑定持久billingCallId；查询、重复通知、重启扫描只能推进同一个计费对象。禁止在结果不明时为了计费确认而重新提交任务。

### 4.4 持久结构草案

| 表 | 职责与唯一约束 |
|---|---|
| `billing_account` | tenant主键，CNY，余额/credit/held/version投影；余额允许负，held非负 |
| `billing_project_limit` | tenant＋project唯一，限额及累计used/held；限额具体周期另见D5 |
| `billing_price_version` | 不可变价目与计量器合同；模型/操作/版本唯一 |
| `billing_call` | callId主键，租户/项目/key、冻结价目、estimate、状态、最终attemptId |
| `billing_attempt` | attemptId主键、callId、真实来源、结果、usage及原币种成本状态 |
| `billing_entry` | 追加充值/消费/冲正/核对，操作幂等键唯一，关联原流水；不更新旧流水 |
| `billing_archive_manifest` | 归档范围、高水位、条数、摘要与可核验状态；保留幂等索引 |

投影与流水同事务，不在每次准入SUM全部流水。归档先封存终结范围、写manifest并验证恢复，再清理在线明细；保留历史幂等标识和余额锚点，未知/活动调用不能被归档。新迁移追加于V9之后，旧版本DDL保持不变，升级前备份，失败不推进schema版本。

## 5. 调用正文记录

### 5.1 保存范围

保存调用方输入/对外输出的文本和结构化事件，关联每次上游尝试的元数据、usage与错误证据；不默认重复保存转换前后所有正文。工具调用及工具结果中的合法文本属于正文，附件、内嵌Base64、多媒体原件只存元数据和引用。URI中的凭据、认证头、已知供应商密钥、续接信封中的认证材料不得落盘；任意用户文本无法承诺识别所有秘密，不能以“排除凭据”宣称自动识别一切敏感数据。

记录的是供应商返回的思考内容，不构造或声称获取供应商未返回的内部推理。未知字段采用协议字段分类；无法安全分类则将该记录标记为不完整并触发健康策略，不将整段原始JSON作为脱敏失败的兜底。

错误隔离：客户非法JSON或不支持的正文结构按该请求拒绝/标记，不改变全局存储健康；只有真实写入失败、队列/空间不足等记录设施故障触发全局准入闸门。否则恶意畸形输入可造成全局拒绝服务。正文索引在open/finish等生命周期更新，不逐SSE片段占用共享数据库事务。

### 5.2 数据路径与故障

recording-api定义`RecordingStore.open(RecordingStart) -> RecordingHandle`，handle提供有界`append(RecordedEvent)`和`finish(RecordingOutcome)`。参数不带HTTP或Reactor对象。两引擎在传输buffer释放前完成有界复制，保留调用事件顺序；不二次订阅响应，不重新拉取上游，不用无界队列，不累计完整SSE。

准入先确认记录存储健康、队列/空间可接受，并创建持久索引；无法满足则在提交上游前拒绝。短暂排队不能被无限制地当作“持久成功”。首版建议将元数据/索引与账务放同权威DB，正文分块写实例目录；写入失败时健康闸门拒绝后续新调用，已在途继续转发。失败的记录保留已写片段并标记INCOMPLETE及原因，不伪造COMPLETE。

状态独立为OPEN、COMPLETE、INCOMPLETE、EXPIRED；启动将无法确认完整的OPEN标记INCOMPLETE，正文恢复不触发费用退款。完成写入与文件原子改名/索引更新通过恢复扫描处理跨文件/DB窗口，不假设两者可原子提交。

全局字节限额、最小剩余磁盘、内存队列字节数、分块大小、单调用限额须有显式配置与测试。达到边界不能静默截断再声称完整；上限与慢写恢复阈值属于容量设计，需2C2G实测后定值，不能推断7天一定放得下。故障恢复须探测写入与剩余空间，避免一次成功即频繁开关闸门。

### 5.3 管理与清理

正文7天可配置，到期按小批次清理正文，不删除金额流水。平台/租户/项目管理员按真实scope访问；观察者仅元数据。API按callId解析持久scope后授权，不信任查询参数声明。查看与导出先记审计再开放正文，导出分页/流式、有界并发、禁止路径遍历；legacy admin token不能绕过新权限。

正文、账务、管理审计三类retention分开。审计长期存储窗口/归档规则尚需容量设计，不能跟随正文过期或将一次导出当成永久保存证明。

## 6. Gemini协议适配

首版明确锁定`generateContent`、`streamGenerateContent`合同。对外路径携带model，不能直接套用现有JSON body的model解析；统一路径模型优先级并对冲突拒绝。上游凭据由路由secretId解析，使用受保护认证策略，客户凭据不得流向供应商。路径构造按segment编码，限制上游目标和API版本，防止model变为任意路径。

官方资料核查：生成接口有独立非流/流方法；`usageMetadata.promptTokenCount`含缓存输入，`cachedContentTokenCount`为其子项，另有thoughts、tool-use与候选用量，不能与total全部相加。[生成接口与usage定义](https://ai.google.dev/api/generate-content)、[计量说明](https://ai.google.dev/gemini-api/docs/tokens)。正文中的这些字段解释是来源事实，具体销售规则不是Google替平台决定的规则。

Gemini原生透传保持JSON/SSE字节语义，只旁路提取治理及记录信息；终止判据按该协议建模，不能强求Chat的`[DONE]`，也不能从普通EOF自动推断成功。安全拦截、无candidate、工具终态、usage-only尾帧、多candidate和截断均有独立fixtures。

Gemini↔Chat经现有语义合同连接，保留system、多轮、tool call/result关联、思考续接及多模态引用；工具不在网关自动执行。接口无法表达的供应商签名/能力，使用既有项目绑定续接机制或明确拒绝，不能伪造思考签名。先扩展语义合同的必要部分，再适配codec，不在引擎散布协议JSON分支。

原生Gemini文件上传、缓存管理、Interactions API、Live和云IAM不因滚动官方文档存在就自动纳入范围。双向Chat转换也不意味着使用DeepSeek上游时支持其不具备的图片理解；按实际route能力检查。

## 7. 恢复与长期运行

恢复目标：宿主机或磁盘损坏，备份恢复点距故障不超过1小时，4小时内完成数据恢复、账务/吊销核对并安全重开。此目标包含人工核对时间，若缺口证据拿不到则目标未通过，不能绕过核对开闸。

复用现有OnlineBackup，先测`VACUUM INTO`对共享连接的等待影响；若影响不可接受，再设计独立只用于备份的连接并证明同库一致性与关闭所有权。SQLite官方支持一致性备份及VACUUM INTO，不支持把正在写入主文件的普通复制当一致性备份。[官方备份说明](https://www.sqlite.org/backup.html)

备份manifest包含数据库schema、资产摘要、账务高水位、正文索引/文件一致性状态、引用的归档清单与根密钥标识；根密钥本体独立保管。复制到独立故障域且验证成功后才更新lastSuccessfulBackup，备份失败/过龄告警。定时周期必须留上传与验证余量，不能每小时启动一次就声称RPO≤1h。

恢复默认maintenance：验证备份/根密钥/归档 → 恢复索引和账户 → 核对缺口充值凭证、供应商用量、Key吊销证据 → 审计确认重开。备份缺口的证据要在故障磁盘以外可获得；同一份旧库不可能自行证明其丢失的消费或吊销。

容量验收：分别测试10万/100万历史结算记录、混合调用与正文记录、并发管理、后台清理和备份，观察延迟分布、错误率、DB等待、WAL/队列/正文空间、未知预留与GC。至少一轮24小时长稳是建议验收场景，不是已完成结果；本次不给未测的吞吐数值承诺。

## 8. 已确认收费规则索引

| 编号 | 问题 | 建议方向 |
|---|---|---|
| D1（已确认） | 网关精确/语义缓存命中 | 客户调用费为零；辅助上游成本由平台承担，独立记录；已预留金额幂等释放 |
| D2（已确认） | CNY存储精度、舍入及小额费用如何累计 | 入账精度6位；租户持久累计尾数，合并计价后完整单位入账；预留向上取整，流式片段不分别取整 |
| D3（已确认） | files/batches/transcriptions及附加工具服务如何收费 | 文件上传/查询/删除与任务查询显式零价，成本平台承担；批量执行、转写、付费工具独立价目，缺规则拒绝，异步查询不重复收费 |
| D4（已确认） | 客户端重复提交是否具有跨请求幂等 | 支持同项目显式幂等键，冲突拒绝；流式重复仅返回原callId与状态；确定结束后默认24小时可配置，执行/未知待对账不因TTL失效 |
| D5（已确认） | 项目金额子限额周期 | 累计额度，以已消费＋在途预留准入；调整不清历史或在途，不增加租户信用；超估算结算可超子限额，后续新调用受限 |
| D6（已确认） | 未给输出上限、非文本单位预估 | 模型计量器估输入、请求上限估输出，未指定用显式模型默认估算值；非文本按数量/规格/时长等规则估算；缺规则拒绝、不隐式改请求 |

D1–D6已逐项确认，不再作为未决产品问题重复询问。硬件路径、队列阈值、索引及批量大小属于实现设计，要用实测验证并公开配置。具体模型售价和估算数值是运营配置，不提供虚构的供应商全覆盖默认值。

D4接入约束：使用独立于X-Request-Id的显式幂等键，先进行当前调用凭据及scope授权，再检索原调用，不能借历史幂等结果绕过吊销、模型权限或跨项目限制。请求摘要包含方法、操作路径、对外模型及影响执行的参数，不只比较正文；价格/路由在原调用中冻结，不能因重放时配置变化再次执行。持久防重记录须在上游提交前完成；崩溃提交结果未知时不重发，不承诺与外部上游跨系统exactly-once。流式重放不能直接使用已脱敏/去附件的正文记录重构字节保真响应。

D4流式行为已确认：重复提交仅返回原callId与状态，不重放已输出SSE；不接入原在途流、不重新执行、不新增收费。响应须明确为重复请求状态，不能伪造空的成功模型输出；HTTP状态和各入口错误/状态载荷在接口合同中显式定义，不以普通SSE 200冒充完整结果。

D4有效期已确认：确定结束后默认24小时、可配置，执行中或结果未知待对账的调用不因TTL失去防重保护。截止边界使用持久时间与可注入Clock测试，不能依赖进程内TTL；过期可作为新调用，不复用旧callId或把旧结算再次计入新调用。请求幂等索引过期不删除账务结算防重、未决任务关联或历史流水。

## 9. 验收与实施顺序

统一发行验收，不拆成三个产品版本。计费、记录、Gemini和恢复可拆独立任务审阅，各任务先用确定性失败测试验证边界，再实现最小改动。

| 任务组 | 必须证明 |
|---|---|
| 金额基础 | 防重充值、重复冲正拒绝、并发透支准入、重启未知保留、价格冻结、错scope/错单位/溢出拒绝 |
| 数据面计费 | 同一调用最终尝试仅收费一次、失败成本独立、取消已知收费/未知挂账、token与金额准入补偿不漏、终态落盘失败不丢预留 |
| 异步任务 | 创建→来源固定→轮询→完成/失败→重启，跨key同项目可见、跨项目拒绝、重复终态不重复收费 |
| 正文 | Base64/附件/认证信息不落盘、任意分块UTF-8与工具参数重组、慢写/队列满拒绝新调用、在途继续、不完整可见、7天清理不删账务 |
| 权限 | 四角色×真实scope、正文查看/导出审计失败拒绝、CSRF与legacy旁路拒绝、金额写入与审计原子 |
| Gemini | 两引擎原生及Chat双向、工具/续接/多模态拒绝路径、终态/截断/取消/usage、路径模型与凭据隔离、命名发现失败 |
| 恢复容量 | 24h混合长稳、历史增长、备份期间准入、独立目标恢复、错误根密钥/损坏manifest/缺口未核对禁止重开 |

默认、独立Redis、jtokkit/otel分别验证；固定LLMGW_TEST_JAR避免profile覆盖。新增运行保留commit、产物摘要、场景、测试计数、跳过项和未覆盖范围。涉及协议/AOT必须验证双引擎native；Linux发行native与本机快速native分开报告。无真实供应商凭据时用合同mock但明确实际供应商未验收，不把mock写成生产兼容证明。
