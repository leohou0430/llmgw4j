# 网关四阶段交付设计

状态：用户已确认设计及代表性场景集，暂不开始；非实现完成声明。日期：2026-11-12。

本设计汇总[24项访谈决定](../../plans/2026-11-12-roadmap-interview.md)，替代继续零散提问。下文标为“工程建议”的内容由设计者提出，整体批准前不视为用户已选择。不自动提交、推送或发布。

## 1. 意图、交付边界与现状

先面向内部团队，将不同客户端的大模型协议收敛到可验证的上游调用；最终保留个人及商业多租户范围。按用户顺序交付：真实业务验收 → Files流式化 → 文件/任务目录及列表 → 控制面。协议转换是第一阶段验收的前置工作，而非既有能力。

当前已有双HTTP引擎、原生扩展图、同协议路由、治理、调用鉴权、部分资源来源绑定和管理API。现有上传/原始响应依赖byte[]；Files/Batches列表未完成；只读console不提供人类登录和分级RBAC。历史SDK、native和容量报告仍为历史证据，不能证明本设计交付。

四阶段全部运行组件合计2CPU/2GiB、单副本：单Java进程承载数据面、管理API和静态网页，嵌入SQLite保存元数据。无生产Node进程、独立数据库或文件原文长期存储。构建与测试工具不计产品运行预算。

不纳入首期：网关任务执行队列、持久调度器；音频/视频字节通路的流式改造；DeepSeek以外的真实供应商；DeepSeek原生Responses/Messages上游；企业SSO、跨副本配置一致性、财务硬预算/收费平台。最终多租户方向保留，这些不构成本轮交付承诺。

## 2. 方案与取舍

| 决策 | 采用方案 | 其他方案及取舍 |
|---|---|---|
| 部署/存储（Q20–21） | 单Java进程＋SQLite，总预算2C2G | Java＋独立数据库仍可合计2C2G，但增加服务及资源分配；用户选择嵌入方案 |
| 协议（Q4、12） | 网关承担三入口→上游Chat语义转换 | 供应商原生兼容入口减少网关转换工作，却不能完成用户要求的自有转换；完整3×3增加首期范围 |
| 原文（Q18） | 元数据＋上游引用 | 自存原文可提供独立下载，但增加存储/保留/删除责任；未选择 |
| 控制面（Q22–23） | 管理网页＋API、内置登录＋RBAC | API-only不满足所选交付；首期OIDC依赖尚未提供的企业身份源 |
| 资源归属（Q15–16） | 租户→项目→多key，资源归项目 | 按key永久独立隔离更接近旧实现，但不能满足项目共享 |
| 任务（Q24） | 上游异步任务目录 | 自有执行队列和崩溃恢复调度属于另一种产品责任，用户未选择 |

工程建议：用共同的语义合同与独立协议编解码适配器，避免每对协议各写一套互相调用的转换器；保留现有同协议通路，但对已配置的DeepSeek收敛路由同样执行能力校验，不能绕过严格策略。

## 3. 第一阶段：三协议转换与真实业务验收

### 3.1 协议合同

对外Chat Completions、Responses、Messages均路由到DeepSeek Chat，固定deepseek-flash。响应及SSE必须还原调用方协议，而非仅重命名URL或事件。核心语义包含有序内容、多轮、工具标识/参数/结果、停止原因、usage、思考状态和图片引用。

工程建议的第一版能力矩阵：

| 能力 | 必须实现与验证 | 无法等价表达时 |
|---|---|---|
| 文本/多轮 | system及用户/助手上下文顺序，文本分段，停止原因 | 拒绝无法保留优先级/语义的组合 |
| 客户端工具 | 工具定义、call id、参数增量拼装、工具结果与续轮关联 | 不支持的服务端工具或工具选择约束明确拒绝 |
| SSE | 各协议合法事件顺序、块/条目生命周期、一次终态 | 提前EOF、非法JSON、缺终态不能伪造成功 |
| usage | 区分输入/输出及可表达的细分；缺失为未知 | 不把未知计成0，不自行推算为供应商实测 |
| 思考 | thinking开关、可表达的推理输出/续轮状态 | 精确预算、供应商私有签名等不可等价能力默认拒绝 |
| 图片 | 支持的内联/上传文件引用转换，项目归属校验 | 不支持格式/引用/来源明确拒绝，不静默去图 |

思考不是“把reasoning_content塞进普通文本”。工程建议：以显式推理内容和续轮状态作为内部独立类型，分别验证三协议可接受的编码；不把供应商原文推理伪称总结，不伪造Anthropic供应商签名。若目标协议要求无法原样提供的受保护状态，可设计有明确网关命名空间、完整性校验和项目绑定的续轮封装，但必须证明客户端往返可用，且不得冒充供应商原生签名。该封装是待技术验证建议，不是已证实等价映射。

**技术准入门槛**：实施先固定官方schema/SDK版本，写出逐字段和事件映射表，验证思考输出及续轮可表达性；若任一必测能力无法满足，则列为阻塞并回报，不得以“全部拒绝思考”或改成普通文本来完成本阶段，也不得擅改用户范围。Responses的previous_response_id/store、内建工具、后台执行和Anthropic私有块等未实现语义明确拒绝；不自动引入对话长期存储。

错误工程建议：输入不兼容返回400及稳定的能力错误码、字段路径和原因；上游不支持的资源操作返回501；授权/不存在对外统一404以避免枚举。SSE头已发送后的错误按客户端协议发错误事件并终止，不能再伪造HTTP状态或成功结束。

降级工程建议：使用网关扩展头枚举具体允许降级的能力，默认空集合；记录请求授权和实际执行降级。禁止一个全局开关默许所有未知字段。映射表列出允许项及语义损失，未列出的拒绝；不得透传该授权头到供应商。需要降级的路径必须有显式授权正例和未授权拒绝反例。

### 3.2 代表性业务场景集（本设计提交批准）

每种对外入口覆盖：①非流式文本与多轮；②流式文本与usage；③工具调用→客户端执行→工具结果续轮；④思考输出及至少一次携带所需状态的续轮；⑤图片理解；⑥客户端取消后释放并恢复。另有未知字段、不可表达约束、损坏/截断SSE及跨项目资源引用的受控合同反例。

工程建议使用无个人信息的固定文本、可判定结果的简单计算工具、附带已知图形/文字的自有小图片；断言结构和语义，不匹配随机措辞。具体JSON、图片摘要、预期结果先固化为版本化fixture，任何改变范围或新增付费上限须重新确认。图片内联用于第一阶段，Files引用在第二/三阶段补回归，避免倒置用户顺序。

生成请求计划上限：每入口9次（文本2、流式1、工具2、思考续轮2、图片1、取消1），三入口共27次；不足以提供供应商要求状态时可减少新增调用并报告阻塞。第一阶段使用内联图片，不等待Files引用能力。60次是上限而非必须用满；余量仅可用于本次10分钟窗口内预先列明的额外场景，不自动重试失败或未知提交。后续Files阶段用真实非生成操作及受控图片引用合同验证，不暗中追加另一轮生成验收。

### 3.3 真实运行和证据

用户边界：10分钟负载窗口、最多60次上游生成请求、并发1、每请求输出上限请求值1024 tokens、SDK及网关均关闭自动重试/fallback。工具续轮、失败、超时、取消但已发送都计数；发送前持久化计数预约，崩溃后未知提交按已使用处理，避免重跑突破授权。计数器为本次验收工具，不是生产金额账本。

工程建议全批次使用同一run id和追加式脱敏记录；按场景轮转低速分布到窗口，600秒或60次任一达到即停止新增。晚结束请求单独记录收尾时间；不得把较长drain伪称10分钟负载。第一阶段窗口结束后未用额度不自动延长或开启另一窗口；如后续需要新增真实生成补验，需另行确认时限及剩余次数使用方式。首次真实窗口选一个明确引擎；双引擎先做相同受控合同，真实额度不按引擎翻倍。

通过：所有必测场景至少完整成功一次；预期不支持正确拒绝；网关错误、静默语义丢失、OOM和取消后泄漏为0；符合2C2G及次数边界。供应商错误单列；必测未成功则不通过。延迟、首字节、资源趋势仅观察；这是10分钟短时业务验收，不是长期稳定性或生产SLO证明。最终新增控制面后需重新验整体资源预算，不能引用第一阶段资源结果代替。

凭据通过安全环境/secret来源输入，不进仓库、命令行参数或报告；仅记录变量标识和脱敏供应商。批准设计不授权新的供应商、模型或超过60次的调用。

## 4. 第二阶段：Files有界流式传输

仅Files上传及供应商确实支持的内容下载。64MiB/文件、66MiB/multipart请求、64KiB/非文件元数据、每进程最多4个并行Files传输，并计入现有总并发；普通JSON限制独立保留。

工程建议扩展原生请求/响应字节契约：JDK Flow＋CompletableFuture；明确chunk所有权、只订阅一次、有限demand、取消与关闭责任。WebFlux复制或转移有明确生命周期的buffer，禁止引用已释放池内存；VT桥用有界队列/读写，不退回整包byte[]。不改正常完成为transport.cancel。

multipart工程建议：认证及全局/Files准入在读取正文前完成，流式扫描边界、文件计数和metadata上限；元数据位于文件后方时采用有界临时spool，不要求官方客户端新增自定义路由字段。每传输临时原文预算最高66MiB、总计264MiB，并预留磁盘安全余量；文件区分离且权限受限，请求结束/取消/异常立即清理，启动清理遗留。磁盘配额/空间不足提前拒绝，避免边收边无界扩张。不是所有上传均必须落盘；只在前置校验依赖后置字段时使用。

已知长度超限前置413；未知长度按实际字节累计拒绝，取消上游并关闭输入，生命周期许可仅释放一次。客户端慢读/慢写、上游慢读、首字节/空闲超时均有回归。超限被发现前上游可能已接收部分数据，报告未知/失败，不宣称供应商一定没有创建资源。

当前核对的[DeepSeek Files资料](https://api-docs.deepseek.com/guides/files_api/)列出上传、列表、元数据及删除；未验证原文下载，不能承诺该供应商内容下载。下载合同用明确支持下载的受控上游验证，报告区分真实与受控。

## 5. 第三阶段：项目资源目录和列表

资源归tenant/project；同项目多key按授权共享，跨项目隔离。持久条目包括网关ID、类型、上游ID、来源路由/供应商/配置版本、创建时间、可观察状态、元数据、最后同步时间和删除标志。保存来源配置的必要引用，不因默认路由切换把旧资源请求发往别的供应商；密钥轮换采用同来源的新凭据，来源被撤销则明确不可访问。

工程建议网关资源ID与上游ID分离，目录操作先查项目授权再访问固定来源。上传/任务创建成功后先提交目录再回成功响应；上游已创建但目录提交失败时记录脱敏待核对事件，返回结果未知，不能谎称原子跨系统事务。无供应商幂等合同就不自动重发创建，也不宣称exactly-once。

列表从本地目录分页，不把供应商账户全量文件暴露给项目。工程建议按创建序号＋ID稳定排序，签名游标绑定租户/项目/筛选条件及首屏高水位；后续新增不混入同次遍历，删除可导致页面减少；需要刷新获取新资源。限制页大小、过滤项及数据库查询时长。上游状态注明最后观察时间，供应商不可用时允许读目录并显示陈旧状态，不能伪装实时成功。

任务仅为已有上游batch/video等异步资源的目录、元数据、状态、分页与已有查询/取消操作。无网关执行器、队列或恢复调度。DeepSeek未支持/未验证的任务API只做受控上游合同，不冒充真实供应商任务验收。

删除/取消工程建议采用pending→confirmed/unknown状态，只有上游确认才标完成；删除目录条目不代表上游已删除。非幂等操作不自动重试；超时unknown可人工触发查询核对。没有原文持久化或供应商下载能力时明确拒绝原文请求。

旧资源工程建议：旧key空间独立保留；显式tenant/project映射和人工审核迁移记录后才共享。缺少归属证据的资源不能按新项目猜测归属，也不能通过扫供应商全账户导入。兼容入口限原owner读取，迁移后遵循新项目授权；迁移过程提供预览、冲突拒绝与审计，不自动合并。

保留工程建议：活跃目录不按短TTL静默遗失；已删除条目和审计按可配置保留策略清理，默认删除墓碑30天、详细审计30天。启动配置数据库/审计空间上限、磁盘剩余保护和清理策略；达到安全阈值拒绝需要持久化的新建/变更，不无声丢审计或删活跃资源。保留时长为本设计建议，可在审阅中调整。

## 6. 第四阶段：可操作控制面

同Java应用提供网页＋管理API，菜单覆盖租户/项目/key、路由版本发布/回滚、文件/任务目录、用量和审计。先满足功能/权限闭环，具体视觉布局交由实现阶段设计；不新增生产Node服务。

### 6.1 身份与权限（工程建议动作表）

| 动作 | 平台管理员 | 租户管理员 | 项目管理员 | 项目只读观察者 |
|---|---|---|---|---|
| 租户创建/停用、全局供应商来源 | 全局 | 不允许 | 不允许 | 不允许 |
| 项目和成员授权 | 全局 | 本租户 | 仅本项目的较低权限成员 | 不允许 |
| key创建/轮换/吊销 | 全局 | 本租户 | 本项目 | 不允许 |
| 路由版本发布/回滚 | 全局及项目 | 本租户项目 | 本项目允许的来源范围 | 不允许 |
| 目录元数据、用量、脱敏审计 | 获授权范围 | 本租户 | 本项目 | 本项目 |
| 文件删除、任务取消 | 获授权范围 | 本租户 | 本项目 | 不允许 |
| 原始凭据/密码哈希读取 | 不提供 | 不提供 | 不提供 | 不提供 |

跨租户或越权对象访问统一拒绝；不允许项目管理员为自己授予租户/平台角色或引入未经允许的上游地址。人类登录与调用API key分离；每个接口在服务器校验scope和动作，不能靠隐藏按钮实现权限。

登录工程建议：成熟密码哈希实现、随机服务端会话、HttpOnly/Secure/SameSite cookie、CSRF保护、登录限速、会话过期和吊销；更改密码/权限后失效相关会话。首个管理员通过一次性本地bootstrap创建，默认无密码/公网注册，不输出固定默认凭据。控制面必须TLS部署，首次初始化不暴露公开自助注册。密码算法和依赖版本由实现者结合Java/native验证选择，不自行实现密码学。

旧X-Admin-Token工程建议：新控制面模式默认禁用旧token远程管理；显式开启的迁移模式限本机/受限管理网，仅作可审计紧急平台权限，不等于普通登录会话，旧只读页面须迁移。不能保留一条无scope后门绕过新RBAC。调用方JWT现有能力继续独立验证。

### 6.2 持久化、发布及恢复

工程建议SQLite保存账号/角色scope、租户/项目/key摘要、来源和配置版本、资源目录、管理审计；供应商密钥加密保存，根密钥从数据库之外安全注入，明文key只在创建/轮换时显示一次。读取接口掩码；备份同时说明根密钥恢复前提。原文文件不入数据库。

路由草稿→校验→不可变发布版本→本进程原子激活。采用期望版本防止并发覆盖，回滚生成新版本并引用目标，不重写历史。持久发布与内存激活间崩溃通过启动恢复已提交版本解决；回响应注明本进程激活状态。新请求使用新快照，进行中的请求及既有资源继续持有来源快照；密钥吊销行为单独定义并验证。单副本不宣称跨副本发布确认。

配置校验含扩展名、模型/协议能力、允许的上游地址/协议、敏感头和超时/容量边界；拒绝任意管理接口地址探测、重定向绕过和DNS变化绕过。来源地址允许规则属于平台权限，项目配置不能放宽。

SQLite工程建议：WAL、短事务、有限写队列和busy timeout；数据库读写不在WebFlux事件循环阻塞。配置/资源变更和相应管理审计同事务，失败则拒绝变更；上游已生效操作仍按unknown补偿核对，不假装跨供应商事务。HTTP请求观察用有界队列及汇总，队列丢弃数可见；不把诊断日志当可靠财务账本。磁盘满必须影响写入成功判断。

备份工程建议使用一致性在线备份或停写快照，覆盖WAL一致性；升级前备份、schema版本迁移及失败回退指引。验证进程强杀/启动恢复、断写、磁盘满、备份还原、密钥缺失和旧schema行为。不承诺多副本共享SQLite写入。JNI解压目录、native资源包含及双引擎native启动必须实测。

## 7. 模块、生命周期和工程自主范围

遵守现有AGENTS边界：core/领域api及实现无Spring、Boot、Reactor；HTTP只在app/双引擎。多实现领域采用聚合parent＋唯一api＋独立实现child；根POM仅聚合。协议适配器依赖本域api，不互相依赖；SQLite通过原生存储合同接入，HTTP桥不二次扫描实现。

扩展使用命名ExtensionModule显式构造，状态归ExtensionContext；seal前显式replace；未知扩展失败。数据库、会话、文件临时区、publisher及执行器必须关闭并验证两个context互不污染。禁止静态有状态注册表。
